## Context

Plan 9.1 asks for Readium's opener and navigator wrapped behind a `ReaderSession`, with Readium's locator and decoration capabilities demonstrated on the chosen release before the contract is committed. Plan 8.3 and 18.1 require that publication scripts and remote resources never run or load, that archive traversal, absolute paths, symlinks, decompression bombs and excessive recursion are rejected, and that protected content yields a clear unsupported-protection error. ADR-0002 pins readium/swift-toolkit 3.11.0. The G0.1 spike (`Spikes/G01-EPUB`, report `Docs/Stage0/G01-EPUB.md`) measured what Readium 3.11.0 does by itself and what an adapter has to add.

### 2. The `ReaderSession` contract

The reading screen is written against a reader-neutral protocol (spike source: `Spikes/G01-EPUB/Adapter/ReaderSession.swift`). Readium types never cross it.

| Operation | Shape | Notes |
| --- | --- | --- |
| open | `EPUBOpener.open(fileURL:) -> Result<OpenedEPUB, ReaderOpenError>`, then `ReadiumReaderSession.make(opened:initialLocator:settings:)` | Errors map to import states (plan 8.2): `unsafeArchive`, `notAnEPUB`, `unsupportedProtection`, `unsupportedLayout` → `unsupported`; `unreadable`, `notARegularFile` → `failed_final`. |
| navigate | `navigate(to: ReaderLocator) async -> Bool`, `goForward`, `goBackward` | |
| return-after-link | `followLink(href:)`, `returnFromLink()`; link taps inside the publication go through the same history | Footnotes and endnotes marked `noteref` are shown in place (`onNote`) and never move the page. |
| current locator | `currentLocator: ReaderLocator?` | |
| selection | `captureSelection() async -> ReaderSelection?` (locator, exact text, prefix, suffix, frame); `currentSelection` (Readium's report, unconfirmed); `clearSelection()` | Called the moment a menu action fires (plan 9.1). Readium 3.11.0 builds the selection locator from the navigator's current location, which can still name the previous resource just after a jump; `captureSelection()` checks the resource against the document that holds the selection, rebuilds the locator for the right resource (text kept, progression dropped) when they differ, and returns nil, so the user is asked to select again, when the selection changed meanwhile. |
| decorations | `apply(highlights: [HighlightPresentation])`: declares the complete set; removing = applying without it | Highlights are database records; decorations only present them (plan 9.1). |
| settings | `apply(settings: ReaderSettings)` | Typeface (Literata, system serif, system sans, publisher), size 14-28 pt, four line-spacing steps, three margins, Paper/Night, paginated/scroll, publisher styles. |
| search within work | `search(_ query: String) async throws -> [ReaderLocator]` | Sylvia's own extraction and FTS5 index (plan 11.3); Readium's search service is not used. |
| observe position | `observePositions(_:) -> ReaderObservation` | |

`ReaderLocator.json` is Readium's `Locator` JSON, kept verbatim and opaque outside the adapter; the other fields are copies for display and the portable anchor.

### 3. Anchors (input to the anchor schema, plan 7.5)

A captured EPUB anchor has portable fields (`asset_id`, `asset_digest`, `resource_href`, `resource_media_type`, `exact_text`, `prefix`, `suffix`, optional `text_offsets` in **Unicode scalars** over Sylvia's extraction with its `extraction_version`, `progression`, `total_progression`, `position`, optional `segment {index, count}`) and an adapter-opaque `reader {adapter: "readium-swift", adapter_version, locator}`. Field-by-field proposal and real samples: `Docs/Stage0/evidence/G01-EPUB/anchor-samples.json`. Rules:

- `exact_text` is Readium's selected string as returned (`window.getSelection().toString()`): never trimmed, collapsed or truncated.
- A quotation that continues into the next resource is stored as several ordered anchors (one per resource, `segment`), and `quoted_text` joins their exact texts. Readium renders each resource in its own web view, so one gesture cannot select across resources.
- DOM and Readium offsets are UTF-16 code units; the adapter converts to Unicode scalars at the boundary (`TextOffsets`). `text_offsets` is null when the selection spans blocks or is ambiguous in the extraction; the opaque locator plus exact text and context still anchor it.
- `position` is Readium's synthetic position (about 1,024 characters each). It is never shown as a page number.

### 4. Safety configuration (plan 8.3, 18.1)

Readium 3.11.0 on its own runs publication JavaScript (inline, external, SVG, event handlers, `javascript:` URLs), lets a publication reach the network (18 requests from the hostile fixture to a loopback recorder in the clean run, including a WebSocket upgrade and a beacon), follows a `<meta http-equiv="refresh">` off the publication, lets any navigation that is not a link activation (a form submission, for example) load any archive entry, including ones the manifest does not declare, opens content-encrypted chapters with no known scheme and serves their ciphertext, reads a whole ZIP entry into one buffer (200 MiB for the bomb fixture), and overflows the stack in its content iterator and search service on 10,000 nested elements. The adapter therefore applies, in this order:

1. **Regular file only.** Directories and symlinked files are refused.
2. **Archive preflight** (`ZIPPreflight`, central directory only, nothing decompressed): reject `..` segments, absolute and drive-letter paths, backslashes, control characters, symlink entries, duplicate names, ZIP-level encryption, methods other than stored and deflate, declared sizes that are inconsistent with the compressed size, more than 10,000 entries, more than 1 GiB expanded in total, any entry above 256 MiB, any deflated entry of 1 MiB or more expanding more than 100:1, any markup or style entry (XHTML, HTML, XML, OPF, NCX, CSS, SVG, SMIL) above 16 MiB, names above 1,024 bytes, and local headers that disagree with the central directory. Values other than the plan's 10,000 entries and 1 GiB are spike proposals to validate against a real library (accepted by the product owner on 22 October 2026 as configurable V1 defaults, PO-02 (a), and rechecked against a larger real-book sample in M3).
3. **Asset retrieval with `file:` only.** A `ResourceFactory` that accepts only file URLs; Readium is never given an HTTP client.
4. **Declared resources only, each by its declared media type** (`DeclaredResourceContainer` in `Spikes/G01-EPUB/Adapter`, `PublicationResourcePolicy` in `Spikes/G01-EPUB/Core`, installed as the publication container in `PublicationOpener.open(onCreatePublication:)`, so the navigator, the content iterator and the search service read only through it). Readium 3.11.0 does not stop a web view from loading archive entries: its spread view cancels link activations only (a form submission or any other navigation that is not a link activation goes through), and `EPUBNavigatorViewModel.serve(href:)` serves any entry the web view asks for, with the manifest's media type or, for an entry the manifest does not declare, one guessed from the file extension. Review R2-01 showed the consequence: one tap on a form button in a script-free spine item declared `application/xml` navigated the web view to an undeclared `evil.html` and to a declared non-spine XML resource, and their scripts ran. The container is therefore default-deny:
   - an entry no manifest link declares (reading order, resources, links, and their alternates and children, compared after Readium's href normalization and with the query and fragment ignored, as `Publication.get` does) is answered with "no such entry", so the web view gets a failed load and Readium's services never read it; this includes the OPF, `META-INF/` and anything left out of the manifest;
   - a declared entry is served by the treatment of the media type Readium will serve it with (the manifest's): `text/html` and `application/xhtml+xml` through the HTML sanitizer below (canonical form, CSP); every other type a web view renders as a document (`application/xml`, `text/xml`, `text/xsl` and any `+xml` type, SVG included) through the non-HTML sanitizer (served only when nothing active is in it); images, style sheets, fonts, audio and video unchanged; anything else (scripts, plain text, JSON, PDF, web archives, a missing or unparseable type) as an empty resource; an href declared twice with different media types is served empty.
   The HTML sanitizer does not edit the publication's text in place; it parses and writes out again:
   - **Parse** the document as XML with libxml2 (`XMLParser`). Named entities from the XHTML 1.x DTDs are first rewritten as numeric references; a DOCTYPE with an internal subset (a `[` outside its quoted identifiers), an entity declaration or an unknown entity name is refused. Parsing stops at the first element deeper than 256 levels, so no tree of a deeper document is ever built.
   - **Write it out in a canonical form**: no comments, CDATA sections, processing instructions or DTD; every `<`, `&` and `>` in text and every `<`, `&`, `"` and whitespace control in attribute values escaped; every element unprefixed, its namespace given by an explicit default `xmlns` where it changes; every non-void element closed explicitly (never `<span/>`, which HTML parsers ignore). While writing, remove `script` elements, embedding elements (`iframe`, `frame`, `frameset`, `object`, `embed`, `applet`, `portal`), `base`, SVG animation elements, `handler` and `listener`, meta refresh and set-cookie, resource-hint links, event-handler attributes, `srcdoc`, `ping`, `xml:base` and any attribute holding a `javascript:`, `vbscript:` or `livescript:` URL, all by local name in every namespace and letter case; and write a Content Security Policy `<meta>` (`default-src 'none'; script-src 'none'; style-src readium: 'unsafe-inline'; img-src readium: data:; font-src readium: data:; media-src readium:; connect-src 'none'; frame-src 'none'; …; base-uri 'none'; form-action 'none'`) as the first child of a `<head>` that is the root's first child, creating the head when the document has none, has it later, or has text directly in the root before it (an HTML parser would start the body at that text and put the later head's `<meta>` in the body, where WebKit ignores a CSP).
   - **Verify the result in every parser that will read it**: libxml2 (WebKit's parser for `application/xhtml+xml`), `SwiftSoup.parse` exactly as Readium's content iterator calls it (it chooses SwiftSoup's XML tree builder for text starting with `<?xml`), and SwiftSoup's HTML5 parser (as WebKit's parser for `text/html`). The document is served only if, in each, there is no script element, event-handler attribute or script URL, the tree nests no deeper than 256, and, in both renderer views, the CSP `<meta>` is the first child of the first `<head>`. The adapter's `cspInjected` statistic is this check, not the fact that text was inserted.
   - **Otherwise withhold**: a document that is not well-formed XML with an XHTML `html` root, nests deeper than 256, has more than 100,000 elements, more than 256 attributes on one element or more than 100,000 attributes in all (namespace declarations count as attributes), fails verification, or is not finished within 20 s is replaced by a "cannot be shown" placeholder (verified the same way) and reported to extraction as `unavailable_excessive_nesting`, `unavailable_unsupported_markup`, `unavailable_time_budget` or `unavailable_verification_failed`.
   - **Bounds**: one linear pass to rewrite entities, one libxml2 pass, three verification parses, no recursion in Sylvia's code; it runs on its own thread with a 64 MiB stack. A worker that runs over budget cannot be stopped (it finishes in the background and its result is discarded). So, per open publication, the adapter records the documents that ran over budget, and later reads of them (Readium reads a document again for each navigator load, content iterator and search) get the placeholder at once instead of starting another worker; and at most two sanitizer workers run at once, a slot being held until its thread really finishes (an over-budget worker included), with the wait for a slot counted against the reading document's 20 s budget (a document that only waited is withheld this time and tried again on its next read). A hostile publication can therefore keep at most two threads busy, for as long as one document takes. Timing on the host (debug build, `sanitizer-timing.tsv`): linear in the input for every pattern measured; the slowest per byte is attribute-dense markup (review R2-02: about three times element-dense markup), which the per-document attribute cap stops below 1 MiB; the slowest documents that are still served, just under the caps, are measured rather than bounded (review R3-01): the slowest, 256 attributes on each of 394 elements, took 4.8 s in the previous committed run and 6.2-13.2 s over three runs in the current one, at a 1-minute load average of about 75 on 18 processors (report F5 gives every run and the load). So the margin to the 20 s budget on a loaded Mac is about 1.5 times. Phone timings are not measured; the hosted test `SanitizerAtCapsTimingTests` times the same documents and device checklist step 11 runs it on the phone.
   Documents a web view renders that cannot carry a page CSP (the non-HTML document types of item 4, anywhere in the publication) are parsed and re-serialized the same way (processing instructions, including `xml-stylesheet`, are dropped). They are served only when nothing had to be removed. Active content, judged after entity decoding: anything in the removal list above, `foreignObject`, form controls by local name in any namespace (`form`, `button`, `input`, `select`, `textarea`, `isindex`, `keygen`), `action` and `formaction` attributes, and any element in the XHTML namespace (WebKit makes it a live HTML element, and nothing in such a document can stop its form submission or meta refresh; review R2-01). Such a document is replaced by a placeholder and reported as `unavailable_active_content`. This withholds every reading-order item declared `application/xml` whose root is XHTML, script-free or not; it has to be declared `application/xhtml+xml` to be shown (report findings F13, F14).
5. **WKContentRuleList** installed on every Readium web view (`setupUserScripts` delegate), compiled per publication (`PublicationResourcePolicy.contentRuleListJSON(readingOrderHrefs:)`): block every load except `readium:`, `data:` and `about:`, and block every document load (a page or frame navigation) except `about:blank` and the publication's reading-order documents, matched as `^readium://<id>/<href>([?#].*)?$`. A publication with a reading-order href that cannot be written exactly as a WebKit URL pattern (a character outside `A-Za-z0-9-_~/%@,;=:!'&.`) gets only the network rules, and the adapter reports that. This is an engine-level layer under item 4: with the container and sanitizers off, it alone stopped every navigation of the R2-01 fixture (simulator, `SafetyTests.testNonLinkNavigationsReachOnlySanitizedDeclaredDocuments`).
6. **Protection.** Reject when Readium flags the publication as restricted (LCP, Adobe ADEPT) or when `encryption.xml` declares any algorithm other than font obfuscation (`http://www.idpf.org/2008/embedding`, `http://ns.adobe.com/pdf/enc#RC`). Never decrypt or circumvent. Font obfuscation alone opens normally.
7. **Compatibility subset.** Reflowable EPUB 2 and EPUB 3 with XHTML content documents declared `application/xhtml+xml` (or `text/html`) in the manifest. Fixed layout is refused (`unsupportedLayout`) for V1. Content outside the manifest is never shown, and a spine item declared as generic XML that contains XHTML is shown as a placeholder (item 4).
8. **External links** are reported to the app (`presentExternalURL`) and opened only on an explicit user action. Note content from the publication is shown as plain text, never through an HTML renderer outside the locked-down web view.

JavaScript stays enabled in the web view: Readium's own user scripts (selection, decorations, pagination) need it. Only reader-owned scripts run; a page CSP does not govern WKUserScripts or `evaluateJavaScript`, and the hostile-fixture test confirms Readium's scripts still work with the CSP in place.

### 5. Presentation

- **Highlight:** a custom `HTMLDecorationTemplate` (`layout: .boxes`, `width: .wrap`): one box per line behind the text (z-index -1), filled with `ochre.tint` and carrying a 2 px `ochre` bottom border; Night uses the dark-theme Ochre pair. Colors come from `Packages/Design` in the product.
- **Literata:** registered through `fontFamilyDeclarations` as a `CSSFontFamilyDeclaration` with the bundled variable roman and italic files (weights 200-900), preloaded; it is the default `fontFamily`. System serif is `ui-serif`, system sans is `-apple-system`. Size maps to Readium's `fontSize` factor of a 16 px root (19 pt = 1.1875); line spacing to `lineHeight`.

### 6. Adapter workarounds for Readium 3.11.0 behavior

All are cheap, all are covered by tests, and all should be re-measured on each Readium upgrade.

- **Selection resource check.** `captureSelection()`, described in section 2. Without it, a quotation captured just after a jump was stored with the right text and the wrong resource (`Docs/Stage0/evidence/G01-EPUB/observations/run-0352-anchor-samples-before-selection-check.json`; regression test output `selection-after-jump.json`).

- **Navigation settle.** A single `go(to:)` into a just-preloaded resource can be undone when that spread finishes loading (observed on the simulator in some runs and not others; `navigation-race.json`). The adapter repeats the jump once after 600 ms; the repeat is a no-op when the page is already in place.
- **Decoration refresh.** After a settings change the adapter clears and redraws the highlight group once the navigator reports its new location, and repairs a highlight that is drawn twice (counted per highlight id in the visible resource).

## Consequences

- The reading screen, capture transaction and search depend only on `ReaderSession`, `ReaderLocator` and the portable anchor; replacing or upgrading Readium touches the adapter and its tests.
- Every Readium upgrade must re-run `Scripts/ci.d/31-g01-epub.sh`. The tests that record Readium-alone behavior (scripts run, network reached, deep nesting crashes, ciphertext served) are written to fail when Readium changes that behavior, so the adapter controls can be revisited deliberately.
- The sanitizer enforces the compatibility subset: a content document that is not well-formed XML with an XHTML `html` root (tag-soup HTML, even when declared `text/html`) is shown as a placeholder and left out of search, with a per-resource status. None of the 195 XHTML documents in the five real fixtures is affected (`sanitizer-real-books.txt`).
- The canonical form changes markup, never text: on those 195 documents the text and the element sequence of the served document equal the original's (host, read with SwiftSoup's XML parser), and in WebKit the text of all 191 reading-order documents is identical with and without the sanitizer (`sanitizer-fidelity-webkit.json`). Foundation's `XMLParser` drops a U+FEFF that starts a reported string, so the sanitizer escapes U+FEFF around it. Every served document starts with an XML declaration, so SwiftSoup inside Readium's content iterator parses it with its XML tree builder (it used its HTML parser for a document without one), and the extraction version is `sylvia-sanitizer-2`.
- The limits (256 levels, 100,000 elements, 256 attributes per element, 100,000 attributes per document, 20 s per document, two sanitizer workers per open publication, and the preflight's 16 MiB per markup entry) are spike proposals for the product owner. *(22 October 2026: accepted by the product owner as configurable V1 defaults, PO-02 (a); if a phone takes longer than 20 s for documents near the caps (device checklist step 11), the choice between lower caps and a longer budget comes back to the owner.)*
- Each publication gets its own compiled content rule list, stored by WebKit under an identifier derived from the rules' content (`sylvia-epub-v2-<digest>`); the product should remove a book's list when the book is deleted.
- Readium trusts a ZIP entry's declared uncompressed size when reading (it stopped at the declared 4,096 bytes of a 200 MiB entry), so the preflight's checks on declared sizes bound what it will inflate. A future Readium that streams past the declared size would need a streaming limit in the adapter.
- Extraction runs in the caller's isolation because Readium's `Publication` is not `Sendable`; the product indexer opens its own `Publication` on a background actor.

## Alternatives considered

- **Readium 2.x APIs or an older pin.** Rejected: ADR-0002 pins 3.11.0; 3.x removes the local HTTP server.
- **Readium's built-in `.highlight` and `.underline` styles combined.** Two decorations per highlight double the bookkeeping and cannot guarantee the underline sits on the fill's bottom edge; one custom template draws both in one box.
- **Readium's search service for "Search this book".** It parses the same text through SwiftSoup without coverage status, chunk mapping or extraction versions, and it crashed on deep nesting; Sylvia needs its own FTS5 index anyway (plan 11.3).
- **Disabling JavaScript in the web view.** Not possible: Readium's navigator is built on its own scripts.
- **Relying on one layer.** In the hostile-fixture test each layer alone stopped every request, but the content rule list alone left every publication script running (only their requests were blocked), while the sanitizer and CSP alone stopped scripts and requests. Review R2-01 then showed that the sanitizer as it stood (HTML, SVG and non-HTML reading-order items only, keyed by declared href) left a path open: a form in a CSP-less XML spine item reached an undeclared entry and a declared non-spine XML resource, both served raw. Each of the two layers now closes that path alone (the declared-resource container with its sanitizers; the rule list's document restriction), and both are kept.
- **A text-level sanitizer** (this spike's first version: regular expressions remove `<script>` elements and insert the CSP after the first `<head>` match; a byte scanner measures nesting). Rejected after review (findings R1-01, R1-02, R1-04): a comment containing `<head>` put the CSP inside the comment and a prefixed `<h:html>` root got none, so publication event handlers ran in WebKit through the adapter; nesting after `<!-->` or behind unmatched end tags was measured as shallow while SwiftSoup built a 10,000-deep tree and the app crashed; and the script pattern took quadratic time (21.5 s for 128 KiB). Each of these inputs is now a fixture (`g01-csp-bypass.epub`, `g01-nesting-bypass.epub`) or a host test.
- **`WKWebpagePreferences.allowsContentJavaScript = false`** (turns off page scripts but not WKUserScripts or `evaluateJavaScript`). Not evaluated: Readium 3.11.0 builds a fresh `WKWebViewConfiguration` for each spread, decides navigation policy in its own `WKNavigationDelegate`, and gives the delegate only its `WKUserContentController`, so using it needs a Readium hook or reaching into Readium's web views. The engine-level layer that is reachable through that hook is the content rule list, which now also restricts document loads to the reading order (section 4 item 5). `allowsContentJavaScript` is worth asking Readium for as a further layer; it would not replace the sanitizer, which also protects Readium's own parsers.
- **Extracting the EPUB to disk.** Not needed: Readium reads entries from the archive, and the spike showed it writes nothing outside the app container.
