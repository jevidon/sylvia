# ADR-0011: AI providers, context packs, consent, network policy and credentials

- **Status:** Proposed
- **Date:** 2026-10-06
- **Deciders:** pending (product owner; security reviewer for the credential and network sections)
- **Plan references:** Sections 2.2 (I-04, I-06, I-07), 4.4.6, 10.4, 11.2, 13, 14, 18.1, 20.3, Appendix A.2 and A.4; tests T24, T30-T33, T48; gate G0.5 (AI part)

## Context

Plan 14 asks for three text dialects behind one provider-neutral interface, a separate speech interface, a request lifecycle that never shows a partial or uncertain answer as complete, consent before any content leaves the device, no fallback between providers, credentials only in the Keychain, and HTTPS except for narrowly scoped local endpoints whose ATS behaviour has been tested. Plan 13 asks for a ContextPack built and stored before sending, four user-chosen scopes, a labelled token budget, a spoiler boundary enforced by filtering, and citations resolved against the pack. The G0.5 spike (`Spikes/G05-AI`) built and tested each of these; the evidence is in `Docs/Stage0/G05-AI.md`.

## Decision

### Provider interfaces and adapters

- `TextGenerationProvider.streamGeneration(GenerationRequest) -> AsyncThrowingStream<GenerationEvent>` with provider-neutral events: `text`, `refusal`, `usage`, `status` (accepted, reasoning omitted, tool call rejected, finish reason missing, delivery as stream or single body) and `finished(FinishReason)`. `SpeechTranscriptionProvider.transcribe(AudioClip) -> TranscriptRecord`. Model listing and token counting are optional capabilities, never prerequisites.
- **OpenAI text path: the Responses API** (`POST {base}/responses`, `stream: true`, `instructions` for the system text, `input` as role/content messages, `max_output_tokens`, `store: false`). OpenAI's migration guide (read 6 October 2026) says Chat Completions "remains supported" but "Responses is recommended for all new projects", and that responses are stored by default; Sylvia sends `store: false` on every request. The stream is decoded from its typed events: only `response.output_text.delta` becomes answer text; `response.refusal.delta` is refusal text; `response.reasoning*` events and `reasoning` output items are discarded; any other output item (function, custom or hosted tool call) is rejected; the stream ends at `response.completed`, `response.incomplete` (reason mapped, `max_output_tokens` is an output limit) or `response.failed`/`error`.
- **Anthropic: the Messages API with its own adapter** (`POST {base}/messages`, headers `x-api-key` and `anthropic-version: 2023-06-01`, top-level `system`, `max_tokens`, `stream: true`). Text deltas are accepted only for content blocks opened as `text`; `thinking`, `redacted_thinking` and `signature` content is never emitted; `tool_use`, `server_tool_use` and `mcp_tool_use` blocks are rejected without parsing their input; stop reasons map as documented (`end_turn` and `stop_sequence` complete, `max_tokens` output limit, `refusal` refused, `model_context_window_exceeded`, `tool_use` rejected, others such as `pause_turn` incomplete). A mid-stream `error` event (for example `overloaded_error`) is an uncertain failure, never replayed automatically.
- **Generic OpenAI-compatible chat** (`POST {base}/chat/completions` relative to an explicitly configured base). Only `choices[0].delta.content` is answer text; `reasoning_content`/`reasoning` fields and a leading `<think>…</think>` block are discarded; `tool_calls`/`function_call` are rejected; `finish_reason` maps to the same outcomes, and a missing `finish_reason` is read as a normal end except after a tool call, which always ends as a rejected tool call whatever the server reports (I-04); a normal end is still an answer only if answer text arrived (see Request lifecycle); a server that answers `stream: true` with one JSON body is accepted and reported as not streamed. `max_tokens` is sent (widely supported by compatible servers); `stream_options.include_usage` only when the endpoint is configured for it.
- **Transcription:** OpenAI-compatible `POST {base}/audio/transcriptions`, multipart, `response_format=json`, or `verbose_json` with `timestamp_granularities[]=segment` only when the endpoint is configured with the timestamps capability (OpenAI documents timestamps for `whisper-1` only). A text-chat configuration is never used for audio. The offline queue is durable: each job (clip metadata, the configuration with a credential reference only, and its state) is written at every state change, `sending` before the upload starts, with the clip's bytes beside it and the audio consent; after a relaunch a queued clip stays queued and is sent only by the user or on reconnect under the opt-in policy, a clip awaiting consent asks again, and a clip found in `sending` becomes a failure saying it may have reached the server and is never resent automatically. Audio consent is checked again when a queued clip is sent. One clip has at most one job: a second request for a clip that is awaiting consent, queued or being sent returns that job (a double tap uploads once), and a request for a transcribed clip returns its transcript and never replaces it or the user's correction (re-transcription that keeps earlier transcripts as revisions, plan 11.1, is not built in the spike). A failed upload whose acceptance is uncertain (a server or gateway error, a timeout or dropped connection after sending, an unreadable or oversized reply, a relaunch mid-upload) records that a resend needs confirmation and is sent again only when the user confirms, as for text; a failure that certainly was not processed (for example a 429) can be sent again directly. Segment times come from an untrusted server: a segment whose start or end is not a finite number, is negative, runs backwards or ends more than 1 s past the clip is dropped and counted (`discarded_segment_count`), never converted unchecked. Raw text, segments (milliseconds), language, provider kind, host and model are kept; corrections are stored separately; every transcript carries "Machine transcription · may be inaccurate". Upload limits are configured (default 25 MB, 5 minutes), never assumed from model names.
- **Base URLs** are normalized once at configuration: http or https only, lowercase scheme and host, default port dropped, no user info, query or fragment, trailing slashes and a pasted endpoint suffix removed, repeated version segments collapsed. Endpoint paths carry no version, so a request URL never contains `/v1/v1`. Sylvia never appends `/v1`; a 404 at connection test time suggests it.
- **No model name or subscription tier appears in domain logic.** The model is entered or picked; the live tests take it from an environment variable.

### Network policy

- HTTPS by default, with normal system trust evaluation and no trust override of any kind.
- Endpoint classification shown to the user: **hosted** for `api.openai.com` and `api.anthropic.com`; **local** only for IP literals in 127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7 or fe80::/10; **user-managed** for everything else, including `localhost`, `.local` and other names, Tailscale CGNAT (100.64/10) and MagicDNS names, and public hosts reached through the generic adapter. A user may declare a broader class (for example hosted for a commercial gateway), never a narrower one.
- **Cleartext rule.** HTTP is allowed only when all hold: the user switched on "allow unencrypted connection" for that endpoint; the host is an IP literal in the local ranges above (a name is never enough, because resolution can be spoofed or rebound); the effective class is local; the adapter is not a first-party one. Octal and short IPv4 forms (`0177.0.0.1`, `127.1`) are not treated as local.
- **ATS.** The app never sets `NSAllowsArbitraryLoads`. Proposed: `NSAllowsLocalNetworking` so the cleartext rule above can be used for a local model server. This is not final: on the iOS 26.5 simulator, ATS did not block cleartext to a private IP literal even with no ATS keys (contrary to Apple's documentation for iOS 17 and later), while it did block a public IP literal in all three variants, so Sylvia's own `EndpointPolicy` is the gate that was actually tested for the LAN. The device run (checklist step 1) decides between `NSAllowsLocalNetworking` and CIDR `NSExceptionDomains`.
- **Redirects.** A redirect to a different origin (scheme, host or port) is never followed: the body and credential header never reach the new origin, a local cleartext exception never extends to a remote host, and the user sees "tried to redirect … Sylvia doesn't follow redirects to other hosts". Same-origin redirects are followed.
- **Sessions** are ephemeral: no cookies, URL cache or credential storage; credentials travel only in the header the adapter sets for its own origin.
- **No fallback.** Each request names exactly one provider; a failure of one never calls another (I-07).
- **Bounded responses** (plan 14.5). Every response is bounded in size and wall-clock time, not only by URLRequest's idle timeout (which any trickle resets): a streamed body may carry at most 1 KiB per requested output token (at least 4 MiB) and must end within 600 s, enforced on each chunk and by a watchdog timer that also ends a response delivering nothing (for example a body held back by URLSession's content sniffing); a single JSON answer body is capped the same way and at 8 MiB; a transcription response at 4 MiB and 300 s; error bodies are read for at most 64 KiB and 30 s. The coordinator separately caps the answer text at 16 characters per requested output token (at least 32,768) and the attempt at 600 s. A stream stopped at a cap keeps what arrived within it, ends `interrupted` (or `failed_retryable` with no output) with "sent more than Sylvia accepts …" or "still sending after Sylvia's time limit …", and is never resent without the user's confirmation.
- **Untrusted numbers.** Retry-After is accepted only as delta-seconds digits or an HTTP date and is clamped to one day, so a hostile value reads as "too long to wait" and never overflows a conversion; segment times are handled as above.

### Credentials

- Keys live only in the Keychain as generic passwords with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, not synchronizable, in the data-protection keychain. AI requests are foreground work in v1 (plan 14.4), so keys are not needed while locked; they never sync and never restore to another device, so a restore needs the key re-entered (plan 14.2). Behaviour after lock and reboot is a device check (checklist step 3).
- Configurations, ContextPacks, ask records, exports and the contracts hold only a `credential_ref` (`{"store": "keychain", "account": <uuid>, "origin": "https://api.openai.com"}`). The JSON schemas reject credential-named fields anywhere.
- **A key is bound to the origin it was entered for** (plan 18.1). The origin (scheme, host and port) is part of the reference and of the Keychain item's identity (its account attribute is the account and the origin), and the providers read and send a key only for a request whose origin equals the reference's origin. If a configuration's base URL is edited to another origin, or an imported configuration names a key next to another origin's base URL, the request stops before anything leaves with "The key stored for this provider was entered for a different address, so Sylvia won't send it to {host}. Enter the key for this address in provider settings." This holds on the text path, the connection test (which asks for no consent) and the speech path; a reference relabelled with the new origin finds no key. The contract states the rule and the Python export check enforces it on every configuration instance and fixture.
- In memory a key is a `Secret`: not Codable, every textual form is `<redacted>`, and the only accessor is the one request builders call to set the auth header.
- Provider error bodies pass through a redactor before reaching an error, log or record: the full key, any 6+ character prefix or suffix of it, and key-shaped tokens are removed; length is capped. Diagnostic log events carry kinds, states, counts and hosts only, never prompts, passages, notes, titles, answers or keys.
- No developer-owned key ships. Live tests read keys only from the environment, and only with the explicit opt-in `SYLVIA_LIVE_PROVIDER_TESTS=1`.
- The library has no non-Keychain credential store: the in-memory store used by host tests, like the other test doubles, lives only in the test-support target, and CI fails if one is defined in a library target.

### Consent

- A destination is the provider's origin, effective classification and model. Consent is required before the first request, again when any of those change, and again when a request would share a broader scope (source text, saved thoughts, audio) than was granted. Audio consent is separate from text consent.
- The destination disclosed and consented to is derived from the configuration the request is sent with (`EndpointIdentity.of(config)`, which applies `EndpointPolicy`). A ContextPack naming any other destination is refused when the draft is created, at consent and again at send (`endpointMismatch`), so the origin the user approved is the origin the request reaches and the stored pack is an accurate audit record. Consent is evaluated again at send time for every record, including a draft that was never prepared.
- The disclosure states the destination row "{host} · {local|user-managed|hosted} · {model}", what is sent, listing only what the request carries ("your question", then passages from the work counted by how they were chosen, for example "1 selected passage and 3 nearby passages from {title}" "7 retrieved passages from {title}" or "the whole text of {title} (N passages)", then "N saved thoughts you selected" counted apart so a note is never described as a passage from the book, and "N earlier questions and answers from this conversation" for a text request; only "the audio clip you selected" for a transcription request, which carries no question) and that nothing else from the library is sent, and that the operator's policies apply (or, for local and user-managed endpoints, that Sylvia cannot see whether the server passes requests on). It never says "Secure" or "Private".
- Earlier turns of a conversation are content too: an earlier answer can repeat or paraphrase the notes it was based on. Each turn records the scopes it shared (transitively, including the turns it resent) and its destination. A turn is resent only to the destination it was sent to (same origin, classification and model); a turn asked of another provider or model is left out with a stated reason ("1 earlier question in this conversation went to a different provider or model, so it and its answer weren't sent to …"), and the builder and coordinator refuse a pack that includes one (`historyViolations`; code-checked on contract instances and fixtures). The scopes of included turns count towards consent, and the disclosure names them ("1 earlier question and answer from this conversation, including answers based on your saved thoughts").
- A connection test sends only fixed probe text; the transcription capability test uploads one second of generated silence.
- The connection test is also the route's conformance check (plan 14.1: a gateway is usable only if its route passes; 14.3: invalid response). It passes only when the reply ends normally with answer text. A tool call fails it ("answered the test by asking to run a tool … Configure a text-only route or model"), as do a refusal, a content filter, an output limit reached before or during the reply ("Raise the maximum output for this endpoint") and any other early end. The probe uses the configuration's maximum output (or the 1,024-token default reserve real questions get), so a model that reasons before answering has room to reply.

### Request lifecycle

- States `draft → awaiting_consent → ready → sending → streaming → complete`, alternatives `cancelled`, `interrupted`, `failed_retryable`, `failed_final`. The question and ContextPack are persisted as a draft before anything is sent and again in `sending` before the request leaves. Partial output is checkpointed (every 400 characters or 1 s) and a record found in `sending`/`streaming` after relaunch becomes "Interrupted · partial answer" or, with no output, `failed_retryable` with "may have reached {host}"; the attempt that was on the wire is closed as `connection_lost`, acceptance `uncertain`. A record found waiting to retry had nothing on the wire (only an attempt the server certainly did not take is retried, and the next attempt is written before its request leaves): it says "Retry stopped. … so nothing is pending.", keeps the refused attempt's own ending and is sent again without confirmation (review round 7).
- A request ID (the ContextPack's `request_id`) has exactly one record. `createDraft` for a request that already has one returns that record unchanged, whatever its state, from memory or from the store; concurrent calls share one creation, and a different pack under the same ID is refused. So a second tap on Ask never erases an answer or resets a request that may already be on the wire to "Draft · not sent".
- Exactly one `send` per record runs at a time; a second is refused (the test holds the first send's store load at a gate until the second has ended, so the proof does not depend on timing; review round 6). A stop is honoured at any point: before the request leaves (nothing sent), while streaming (partial kept and labelled), or during a backoff wait. When the app's scene leaves the foreground it calls `stopAll(reason: .suspension)` inside a background task and waits until the stopped records are written (`waitUntilIdle`); the probe app does exactly this and a UI test backgrounds it mid-stream on the simulator.
- Automatic retry only for failures where the generation certainly was not accepted, before any output: DNS, connect, 429, and 503 or 529 from a hosted service or a local server (both say the request was not taken; llama.cpp, for example, answers 503 while it loads a model). A 502 or 504 is a gateway reporting an upstream failure or timeout, so the upstream may already have accepted and billed the generation; a 500 or other 5xx may come after generation started; and a user-managed endpoint may itself be a gateway (Hermes, a commercial gateway, a tailnet proxy) relaying any status from an upstream that accepted the request. All of these are uncertain: the record ends `failed_retryable` with "may or may not have been processed" and is resent only when the user confirms (`ErrorClassifier.serverErrorAcceptance`). Retries use capped exponential backoff (1 s doubling to 20 s, three attempts, jitter between half and full delay) and Retry-After (seconds or HTTP date; a wait over 60 s is not waited out). A generation whose acceptance is uncertain (timeout, connection loss, mid-stream error, or a stop after the request may have left) is never replayed without the user's confirmation. Retries reuse the record: the question exists once. Each attempt records how it ended: its outcome and usage, and, when it failed (an error, a stop by the user or by suspension, Sylvia's output limits, a relaunch, or a final event with no answer text), its failure kind, acceptance and HTTP status; text it received is kept on it when a later attempt replaces the record's answer (review round 7).
- Only a normal end with visible answer text is `complete` with outcome `answer`, and only that reads "Complete" (I-04). After some answer text, every other final event ends `interrupted` ("Interrupted · partial answer", with the reason shown beside it): output limits, context-window stops, incomplete streams, and also refusal stops and content-filter stops, because a filter omits content and a refusal stop cuts the text off where the provider stopped it. With no answer text (whitespace counts as none): a refusal or a content-filter stop ends `complete` with outcome `refusal` or `content_filtered` and shows its classified message instead of "Complete", with any refusal text kept apart from answers (a refusal that sent no text says so: "{host} declined to answer this question and gave no reply to show"); a normal end (only reasoning, only a `<think>` block, or `[DONE]` alone), an output limit or another early end ends `failed_retryable`, and a context-window stop `failed_final`, each with an actionable message (a model that reasons first may need a larger maximum output) and acceptance uncertain, so the generation is resent only when the user confirms. A tool call ends `failed_final` and nothing is executed. A failed record always carries its classified failure; without one its status is "No answer", never "Draft · not sent", because the request may have left the device. Offline submission stays a draft ("Draft · not sent", saved on this device) and is never sent automatically. A record whose request may have left the device becomes a draft again only when the user confirms a resend that can't go out at once: offline, or when the destination needs consent first (`awaiting_consent`, which also reads "Draft · not sent"; for example after a relaunch, since the spike's caller holds the consent ledger in memory, or after a model change). From that confirmation, before the consent check, the offline check and the request, what the record shows describes the resend alone: the earlier attempt's answer and refusal text move to its attempt record, and the record's outcome, failure, usage and reasoning and tool-call flags are cleared. So "Draft · not sent" is never shown beside the earlier partial answer or its "may have been processed" message. The earlier attempt keeps how it ended, whichever way it ended: its outcome when the provider ended it or it produced answer text, and its failure kind and acceptance (`uncertain` whenever the request may have reached the provider) when it failed (review rounds 6 and 7; round 6 covered the offline case only, and stopped or relaunched attempts recorded no acceptance until round 7). Otherwise such a record never reads "Draft · not sent"; the transcription queue sends on reconnect only under an opt-in policy, and that loop checks each clip just before sending it, sends only clips still queued (never a failed one, never one the user is already sending) and never stops at one clip's error.

### Context packs

- Built and persisted before sending (`Contracts/schemas/context-pack.v1.schema.json`, from Appendix A.2 completed per 13.1 and 11.2): question, scope and its fixed chip label, coverage and its label, work snapshot, evidence exactly as sent with local citation IDs `c1…`, SHA-256 of each snippet, origin and source quality, positions (extracted-paragraph ordinals, with the edition they count in), retrieval settings and scores, spoiler boundary and how many items it excluded, included and excluded conversation turns with the reason (each included turn with the scopes it shared and its destination, and its answer with citation markers replaced by `[earlier source]`), budget accounting, truncation disclosure, stated limitations, text coverage, endpoint identity without credentials, prompt template version and a digest of the whole pack. The digest is SHA-256 over an exactly specified serialization (sorted keys, no whitespace, non-ASCII and "/" unescaped; equal to Python `json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=False)`), so a client in another language can verify it.
- Scopes: selected passage; passage and nearby text (up to 250 words each side, same chapter); relevant passages from this work (SQLite FTS5 `bm25` through GRDB 7.11.1, user text reduced to at most 16 quoted terms joined with OR so no FTS syntax is ever interpreted, bound parameters only, top 5 plus one adjacent chunk each side of the top hit); selected thoughts (at most 8). Whole book only when every chunk fits and the user chooses it, never combined with "Do not include later passages". Chunks are 300-600 words on paragraph boundaries within one chapter; an oversized paragraph is split at sentence boundaries.
- Budget: configured context limit, or 8,192 tokens for an unknown model, minus system text, question, included history, output reserve (configured maximum output or 1,024) and a margin (10 %, at least 256). Without a bundled tokenizer every count is a labelled estimate (UTF-8 bytes ÷ 3, which over-counts English). Evidence that does not fit is counted and disclosed; a selection that does not fit is an error, never a silent trim; a context-length error from the provider is shown with "choose a narrower context", never retried with fewer passages.
- Spoiler boundary: a user-confirmed position, else the selection's paragraph; without either, nothing is retrieved from the work. The confirmed position carries the edition it counts in (`ReadingPosition`); under "Do not include later passages" a position from another edition is refused with a message asking the user to confirm a position in this edition or turn the setting off, never applied to this edition's paragraphs (review round 6). The selection is evidence too: a selection after the confirmed position is refused ("Your selection is after your confirmed position … Move your position to the selection, or turn that setting off"), never sent under a boundary that says otherwise and never moved silently. Filtering happens in the SQL query before ranking, adjacent chunks and nearby text stop at the boundary (including a boundary inside a chapter), thoughts on the work beyond it (or whose place in this edition is unknown) are dropped, and earlier turns whose evidence went past it (or whose evidence position is unknown) are excluded with a stated reason. Each excluded turn is counted under the reason that is true for it, in this order: another destination, no position set (a turn that used any evidence while the boundary has no position), another edition, an unknown place (what a turn built from a pack holding a note, even a general one, or a thought from another edition gets), and beyond the position (review round 6; until then the unknown-place and no-position turns were said to be "beyond your position"). A saved thought on the pack's work keeps its work and place (`work_id`, `position`), so the stored pack shows that it lies within the boundary; a thought on another work, or on none, has no place in this one and is not restricted by it. Positions are edition-specific: an ordinal counts one edition's extracted paragraphs, so a saved thought and an earlier turn carry the edition their ordinal counts in, and a position is compared with the boundary, and recorded in the pack (with `edition_id`), only when it is in the pack's own edition. A thought on the work captured in another edition, or with no ordinal, has an unknown place here: a restricted pack leaves it out and an unrestricted pack keeps it without a position or an edition; a turn counted in another edition is left out of a restricted pack with its own reason, and so is a turn whose place is unknown. A turn records its edition but not its work, so a turn about another work is left out as one from "another edition": the exclusion is safe, the reason is wrong (a known limitation, review round 7). Plan 7.2 ties a conversation to one work, so this arises only if M5 lets a conversation span works, which would need the work in the snapshot. Precise boundaries across editions wait for the alignment plan 13.3 describes. As a final check the builder refuses to return, and the coordinator refuses to store or send, a pack with any evidence or included turn after its own `max_ordinal`, with an item from its work that has no position, or with a position or included turn counted in another edition (`spoilerBoundaryViolations`; the same rule is code-checked on every contract instance and fixture, and the schema requires `edition_id` with every position and on every turn that used evidence).
- Limitations the plan requires to be stated are stated by the app, not left to the model: the pack carries `limitations` (codes `no_enforceable_position`, `no_searchable_terms`, `no_matching_passages`, `all_excluded_by_boundary`, `audio_passage_unavailable`, each with a fixed disclosure shown with the request and the answer), a pack that sends nothing has coverage "No passages sent", and the prompt template (since `sylvia-grounded-2`; now `sylvia-grounded-3`) passes each limitation to the model in a `<limitation>` element. A question about a moment in a recording with no transcript or confirmed companion passage gets `audio_passage_unavailable` (plan 10.4); Sylvia never infers ebook text from a timestamp.

### Grounding

- Evidence is sent inside `<evidence id=… origin=… location=…>` elements with `&`, `<` and `>` escaped, so book or note text cannot close an element, open one or forge an ID. The system text says evidence is quoted material, not instructions; that the model has no tools; to cite ids in brackets; to quote exactly; and to say when evidence is insufficient.
- After generation, `[cN]` markers resolve only against the pack's allowlist; anything else stays visibly unresolved with a one-line explanation and no link. URLs in answers are inert text.
- Citation IDs are local to each pack and every pack numbers from `c1`, so an earlier answer's markers are never resent: they pointed into an earlier pack whose evidence is not resent, and would otherwise resolve to the current pack's `c1`. The builder replaces them with `[earlier source]` (template `sylvia-grounded-3` tells the model what that means and to cite only the current evidence), the template does the same for any pack, and the contract rejects an included answer that still carries a marker.
- Claimed quotations are found in Markdown block quotes (consecutive `>` lines, nested ones included; a citation inside the block is its citation, and a last line starting with a dash is an attribution, not quoted text) and in every common quotation style (“…”, "…", ‘…’, '…', «…», ‹…›, „…“), with single marks recognised only at word boundaries so apostrophes are not quotation marks, and a quotation nested in another (including quotation marks inside a block quote) counted once. Any block quote is checked, so one that is not a quotation at all is labelled unsupported rather than shown as a quotation. Quotations of three or more words are checked against the supplied evidence: **exact** only when every word and punctuation mark matches one evidence item as whole tokens, letter case included except the quotation's first letter (which may be capitalized or lowercased to fit the sentence), with whitespace, quotation-mark and dash styles, invisible characters, Unicode compatibility forms and punctuation at the quotation's edges normalized, and ellipsis segments in order, each at least three words; otherwise **paraphrase** (75 % of content words in one item, at least three) or **unsupported**. Both non-exact labels say "not an exact quotation". One or two quoted words cannot establish a quotation (they may be a term or scare quotes), so they are never labelled exact: they get "Short quoted phrase · not checked as a quotation" when the words occur in a supplied passage and "Short quoted phrase · not found in the passages sent" otherwise. A matching quotation cited to the wrong passage is flagged.
- Nothing in evidence, notes or provider output can trigger a tool, a fetch or a metadata change: Sylvia sends no tools, rejects tool calls unparsed and has no code path that acts on answer text.

## Consequences

- Each dialect is isolated in its own decoder; a new dialect is a new request builder and decoder, not a branch through the others.
- Because the simulator did not enforce ATS for private IP literals, nothing in Sylvia may rely on ATS to stop cleartext to the LAN; `EndpointPolicy` is mandatory on every request path (text and speech), and tests must keep covering it.
- `WhenUnlockedThisDeviceOnly` means no AI request can start while the phone is locked, and keys must be re-entered after restoring to a new device. Any future background AI feature needs a new decision.
- Keychain tests need an app host in CI (an unhosted SwiftPM test bundle gets errSecMissingEntitlement, -34018, on the simulator).
- Local Network denial detection reads the network path that URLSession attaches to the error under an undocumented `userInfo` key (`_NSURLErrorNWPathKey`). If iOS stops attaching it, denial is reported as "offline". A device check (step 2) confirms it; a documented alternative (an `NWPathMonitor` or `NWConnection` probe on failure) should replace it before M5.
- The status vocabulary row "Asking a model" has no phrases for failures, a cancel before any output, a refusal or content-filter stop with no answer text, a reply with no answer text, or the reason shown beside "Interrupted · partial answer". The spike shows classified messages there; `Packages/Design` needs keys for them before product UI (open question in the report).
- The spike's ask store (one JSON file per record) and transcription queue store (one JSON file per job, the clip's bytes and the audio consent), both with complete-until-first-authentication protection on iOS, are stand-ins; the production stores follow the persistence decision from G0.5 recovery.

## Alternatives considered

- **OpenAI through Chat Completions.** Still supported and covered by the generic adapter, but OpenAI recommends Responses for new projects, and Responses gives typed events for refusals, reasoning and incomplete states. Rejected for the first-party OpenAI path.
- **Forcing Anthropic through an OpenAI-compatible shim.** Rejected by plan 14.1; it would also lose `refusal`, thinking-block and tool-block distinctions.
- **Treating `localhost` and `.local` names as local for cleartext.** Rejected: names can be spoofed or rebound and plan 14.3 forbids `.local` as the sole check.
- **Scoping keys to an origin only in transit** (blocking cross-origin redirects and setting the header for the configured origin). Rejected after review round 4: the key followed whatever base URL the configuration held, so an edited or imported base URL sent it to a new host, and the connection test did so with no consent step. The origin is now bound to the key.
- **Following redirects but stripping the auth header.** Rejected: the body (passages and notes) would still reach the new origin, and a local cleartext exception could carry over to a remote host.
- **`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` for AI keys.** Not needed while AI is foreground-only; it would widen exposure while locked for no v1 benefit.
- **Moving the spoiler boundary to a selection made after the confirmed position.** Rejected: it would silently widen what is sent past the position the user confirmed; the user moves the position or turns the setting off.
- **Leaving required limitations to the model** (no position set, audio passage unavailable). Rejected: plan 13.3 and 10.4 require the statement; a model may omit it, so the app states it and the model is only asked to repeat it.
- **Truncating an oversized selection to fit.** Rejected: plan 13.2 forbids silent evidence deletion; the user narrows the selection instead.
- **Substring matching for quotation checks.** Rejected after the spike found it labelled "at the end" exact inside "that the endless" and accepted quotations stitched from one-word fragments.
- **Resending earlier turns to a new destination under that destination's consent.** Rejected for now: the turn's answer was written from what the earlier destination received (possibly the user's notes), and asking for consent to resend a whole conversation to a new operator is a larger product decision. Switching provider or model therefore starts the new destination without earlier turns, and the pack says so (open question for the product owner).
- **Citation IDs unique across a conversation** (c1… in the first pack, then c4… and so on). Not chosen: it needs the conversation's citation history at build time and still leaves the earlier evidence unsent, so an earlier ID could never resolve to anything the model saw. Replacing earlier markers with `[earlier source]` keeps IDs local to one pack, as Appendix A.2 describes.
- **Treating every 5xx as retryable** (plan 14.4 lists 5xx among retryable failures). Narrowed: only 503 and 529 from a hosted or local endpoint say the request was not taken; a gateway's 502 or 504, a 500, and any 5xx from a user-managed endpoint may follow an accepted generation, and 14.4 forbids replaying those automatically.
- **Forbidding block quotes in the prompt instead of checking them.** Not chosen: a model may use them anyway, so the check is what guarantees a label.
- **Ending refusal and content-filter stops `complete` whatever arrived before them.** Rejected after review round 3: text before such a stop is cut off, and "Complete" over it breaks I-04. Such text is a labelled partial answer.
- **Treating a normal end as complete without checking for answer text.** Rejected after review round 3: a reasoning model that spends its output budget on reasoning ends normally with nothing to show.
- **Case-insensitive matching for "Exact quotation".** Rejected after review round 3: a changed capital is a change of wording (I-05). Only the first letter may change case, a standard quoting convention; the product owner confirms the rule.
- **Keeping the transcription queue in memory and re-asking after a relaunch.** Rejected: plan 10.4 queues a local draft offline, and a queue that disappears on relaunch loses the user's request silently.
- **Letting a second Transcribe request start a new job for the clip.** Rejected after review round 4: a double tap uploaded (and may have billed) the clip twice, and a later request replaced the raw transcript and the user's correction, which plan 10.4 and 11.1 keep.
- **`createDraft` as an upsert keyed by the request ID.** Rejected after review round 5: a second call erased an answered record and reset a request on the wire to "Draft · not sent", which a relaunch left sendable without confirmation. The existing record is returned instead.
- **Applying a confirmed position to whatever edition the pack uses, or setting aside one from another edition.** Rejected after review round 6. Applied, it marks the wrong paragraphs as read while the pack claims a user-confirmed boundary. Set aside as if none were confirmed, the selection, when there is one, becomes the boundary, silently replacing a position the user confirmed that may lie before it (the same objection as moving the boundary to a selection, above); without a selection, the pack says that no reading position is set, which is false. Turned into "no enforceable position" (basis none), it also refuses a selection as "after your confirmed position", which is false. The request is refused with its own message instead. (Until round 7 this entry gave only the last reason, which holds for the basis-none variant alone: R7-03.)
- **Keeping a resend's earlier answer and failure on the record until the resend is allowed or sent.** Not chosen after review round 7, which found a confirmed resend that needed consent stored as "Draft · not sent" beside them. The user's confirmation is the one point where the record starts to describe the resend, whichever way the resend continues (consent first, offline, or sent at once). Keeping the earlier state while consent is asked would need consent granted on a finished record and a second confirmation after it, or state that is not saved. The earlier attempt keeps its text and how it ended (outcome, failure kind, acceptance, HTTP status and usage), though not the wording of its failure message. Whether M5 shows that attempt beside the draft, or restores it when the consent sheet is dismissed, is a design question (checklist step 9.2).
- **Reading a saved thought's ordinal in whatever edition the pack uses.** Rejected after review round 5: ordinals in another edition count different paragraphs, so a later passage could pass the spoiler filter and be stored with this edition's place. A position is compared and recorded only in its own edition; across editions the place is unknown until an alignment exists.
- **Treating the user's Send as confirmation to resend an uncertain upload.** Not chosen: the failure message says Sylvia won't send it again without asking, and the text path asks; the speech path now asks the same way.
