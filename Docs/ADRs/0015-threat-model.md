## Context

Plan 21.2 lists a threat model among the M0 deliverables, and 18.1 sets its scope: publications, archive entries, provider responses, URLs, source metadata and pairing advertisements are untrusted, and the named threats are malicious EPUB HTML, parser crashes, archive traversal, oversized files, altered source bytes, credential leakage, rogue LAN hosts, prompt injection and accidental destructive deletion. The Stage 0 gates built and tested controls for most of these, each in its own spike and ADR. This record puts them in one place per trust boundary, names where each control lives and what proves it, states what is left, and lists every 18.1 requirement that has no implemented and tested control yet, with the milestone that must close it. It also adds a repository-wide check of the CLAUDE.md hard rules that a script can verify (section 6).

**Every control below is spike code.** `Spikes/` is Stage 0 evidence code that is never shipped (ADR-0002). The product targets that exist today are `Apps/DesignCatalog` and `Packages/Design`, which have no network, archive or credential surface; their one storage surface is the interaction prototype's capture store (B9; corrected on 19 October 2026, final review SEC-04). So no control in this record is in a product yet; each one must be re-implemented, with its tests ported, in the milestone named in section 7.2. "Tested" below means tested in the spike, in the environment named.

## Decision

### 1. Method and words used

- **Method.** One section per trust boundary. Each row is a threat, tagged with its STRIDE category (S spoofing, T tampering, R repudiation or false acknowledgement, I information disclosure, D denial of service, E elevation of privilege), the control, where it is implemented (file and type), the evidence, and the residual risk. Privacy threats are tagged I.
- **Evidence status** uses the Stage 0 words: **host**, **simulator** (iPhone 17, iOS 26.5 unless stated), **pending-device**, **pending-human**. A control that exists only in an ADR is **designed**; one that does not exist is **missing**.
- **Evidence paths** are relative to `Docs/Stage0/evidence/` unless they start with another top-level folder. This record cites the gate reports' recorded runs and did not re-run the gate suites; what was run for this record is listed under Evidence.
- **G0.4 audio** is not merged into this branch. Its controls are read from branch `m0-g04-audio` at commit `943d5e778de2b58f47343f0e146f9e3ed7baa70e`, still in review; paths from it are marked "(m0-g04-audio)". *(Dated note, 19 October 2026: true when this record was written. ### 6. Mechanical hard-rule audit

`Scripts/audit-hard-rules.sh` checks the CLAUDE.md rules that a script can verify, over every committed and untracked (not ignored) file except its own two files, which hold the patterns; `Scripts/ci.d/13-hard-rules.sh` runs its self-test and then the audit, and fails on any finding. Rules: `ats-arbitrary-loads` (never allowlistable), `ats-exception`, `trust-override` (server-trust credentials, `SecTrustSetExceptions`, verify blocks, NIOSSL `certificateVerification` `.none`, disabled evaluators, Python unverified contexts, `curl -k`, `wget --no-check-certificate` and the TLS environment switches), `weak-tls` (minimum below 1.2), `file-protection-none`, `keychain-accessible-always` (never allowlistable), `key-like-string` (provider and cloud credential formats), `private-key-block` and `secret-file` (never allowlistable), `generic-secret` (a secret-named field with a high-entropy value), and `todo-in-product` (TODO, FIXME or an unimplemented `fatalError` in `Apps/**` and `Packages/**` outside test directories). The script's header lists every pattern. Since the M0 final fix (final review SEC-01 and SEC-02): the configuration rules read `.json` files too (an XcodeGen project spec can be JSON); each rule's patterns run over a file's whole comment-stripped text, so a trust override written across two lines is found, and the hit is reported at its first line; `secret-file` also names `.key`, `.keychain`, `.keychain-db` and `.provisionprofile` files; and the audit refuses an allowlist entry whose reason names no ADR. The self-test plants each of these. Since the fix's second round (20 October 2026; final review round 2, CC2-03, a security-lens finding reported by the clean-clone lens): `trust-override` also matches the server-trust credential whose type Swift infers (`.init` with the `trust:` label, as in a delegate that answers every challenge with it), and `weak-tls` also matches a 1.0 or 1.1 minimum set through Network.framework's `sec_protocol_options_set_min_tls_protocol_version`, NIOSSL's `minimumTLSVersion` passed as an argument, and the deprecated SSLProtocol values in their Swift spelling; each form type-checks in Swift 6 on the host except NIOSSL's, which needs that package and is checked as text only, the self-test plants each (across lines too), and G0.2's own guards match the same forms (`M0-Integration/final-fix-2/guard-controls.log`: copies with the earlier patterns miss exactly the new cases). For product code this audit is the only static guard of these rules, so its patterns are the standing check of the trust and TLS rules of B4 to B6 between reviews.

- **Allowlist.** Built into the script, one line per entry with the rule, a path glob, an optional line pattern and the ADR that justifies it (an entry whose reason names no ADR is refused since the M0 final fix). An entry that matches nothing fails the audit, so it cannot outlive the code it excuses. A value that names itself a canary, fixture or example is reported as allowed, not hidden. Matched credentials are never printed (length and first four characters only).
- **Comments.** XML comments in plists and whole-line comments are ignored for the configuration and code rules; block and trailing comments are not, so a hit there must be allowlisted with a reason.
- **What it cannot see.** A trust decision or protection class passed through a variable or wrapper (TM-F2 is an example), binary files, and anything outside the patterns. It complements review; it does not replace it.

**Result on this branch when this record was written** (`M0-threat-model/audit-repository.log`, commit `7d990f6`): 1,922 files scanned (814 binary); **1 finding**, TM-F1; 50 allowed hits: 14 ATS exception keys, all in the never-shipped ATS probe apps of G0.2 (`ATSVariant-*.plist`) and G0.5 AI (`ATSProbe`); 4 trust overrides (the pinned answer in `PinnedSession.swift`, the server-side "no client certificate" setting in `HTTPServer.swift`, and two lines of the G0.2 guard that search for the pattern); 3 protection hits (a readback mapping and a test-only probe of the platform default); 10 key-like strings, 9 of them self-declared canaries or fixtures and 1 redaction-test input; 19 generic secrets (18 contract-fixture values and their generator's fixed values, and the G0.5 AI canary key). No `NSAllowsArbitraryLoads`, weak TLS, `kSecAttrAccessibleAlways`, private key, key file or TODO in a product target. *(Since then: 0 findings after M0 assembly's TM-F1 fix, and at the M0 final fix, with the rules of SEC-01 and SEC-02, 3,019 files scanned (835 binary), 0 findings, 49 allowed hits and 13 allowlist entries in its complete run (`M0-Integration/final-fix/ci-logs/hard-rules/audit-repository.log`), and 0 findings on its last commit (`M0-Integration/final-fix/gate-final-checks.log`, part 5).)* **The G0.4 tree** (`m0-g04-audio` at `943d5e7`, extracted with `git archive`, audited as a plain directory): 190 files, 0 findings, 0 allowed hits (`M0-threat-model/audit-g04-audio.log`).

## Alternatives considered

- **One threat model per feature, written later.** Rejected: 21.2 asks for it at M0, and the gates already chose controls that later milestones must keep; a single record makes the carry-over (7.2) visible.
- **LINDDUN or attack trees instead of STRIDE.** STRIDE per boundary maps directly onto the gate tests; privacy threats are covered as information disclosure plus the B10 logging rules. Attack trees can be added for the M0 security gate's pairing review if the reviewer asks.
- **An off-the-shelf scanner (gitleaks, semgrep, SwiftLint) for the hard rules.** Not installed, would be a new dependency for ADR-0014, and would still need Sylvia-specific rules (ATS allowlist, product-target TODOs). A small script with a self-test checks exactly the CLAUDE.md rules. A dedicated secret scanner can be added later if the owner wants broader credential coverage.
- **Per-gate guards only** (as `40-g02-transfer` has). Rejected as the only control: a rule that holds in one spike says nothing about the next product target.
- **Allowlisting TM-F1 so CI passes.** Rejected: it is a real unprotected-write path; the drop-in reports it until the code changes.
