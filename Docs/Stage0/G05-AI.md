# G0.5 AI: providers, context packs, citations and transcription

Stage 0 report for the AI half of gate G0.5 (plan Section 21.1): each provider dialect plus a local endpoint, a correct context snapshot and citation resolution, and a transcription endpoint. The restore drill is the other half of G0.5 and is reported in `G05-Recovery.md`. The decisions this report supports are in ADR-0011 (`Docs/ADRs/0011-ai-providers-context-and-privacy.md`, Proposed).

**Spike:** `Spikes/G05-AI` (Swift package `G05AI`: `SylviaAI`, `SylviaContext`, `G05TestSupport`; Swift 6 language mode, complete strict concurrency, `ExistentialAny`; builds for macOS and iOS) and `Spikes/G05-AI/ATSProbe` (XcodeGen project: three host apps that differ only in their App Transport Security keys, with hosted tests, plus a UI test that backgrounds one of them mid-stream). **CI:** `Scripts/ci.d/70-g05-ai.sh`. **Device and human steps:** `Docs/Stage0/device-checklists/G05-AI.md`.

**Environments.** *Host:* macOS 26.6.2 (25G83), Apple M5 Max, Xcode 27.0 (27A266a), Swift 6.4. *Simulator:* `Sylvia-M0-g05-ai`, iPhone 17, iOS 26.5 (23F77) (a second runner, such as a reviewer, sets `SYLVIA_G05_SIM_NAME` so the CI drop-in creates and uses its own simulator). *Device:* none; the physical iPhone was reserved for a later serialized run. No provider API was called: no keys exist, and the live tests skip with their reason.

**What "fake" means here.** Every network test talks to an in-process HTTP server the test starts on 127.0.0.1 with an ephemeral port (`G05TestSupport/FakeHTTPServer`), or, for errors that cannot be produced locally (DNS failure, untrusted certificate, Local Network denial), to a `URLProtocol` stub. The fake servers replay the request and event shapes from the official references (OpenAI Responses and Chat Completions, Anthropic Messages and streaming, OpenAI speech-to-text), read on 6 October 2026. A passing fake test shows the adapter handles the documented shapes; it does not show that a real provider or model behaves that way.

## Findings that change scope or approach

**F1. On the iOS 26.5 simulator, ATS does not block cleartext HTTP to a private IP literal, even with no ATS keys.** In all three probe apps the load to the Mac's own 192.168.x.x address on a closed port reached the network stack (URLError -1004, connection refused) instead of failing ATS (-1022). ATS was active: a qualified name was blocked in every variant. Apple documents that from iOS 17 such loads are blocked without an exception. The plan (14.3) allows the HTTP exception "only if the minimum OS's ATS behaviour passes testing"; the simulator result cannot settle that. Approach change: Sylvia's own `EndpointPolicy` (opt-in, local IP literal only, local class only, first-party adapters HTTPS only) is the enforced rule on every request path, with or without ATS, and the Info.plist key is chosen after the device run (checklist step 1).

**F2. Two lifecycle races were found in the earlier work and fixed.** A second `send` of the same record could slip through while the first was suspended loading it, putting the question on the wire twice; and a Cancel tapped while the `sending` record was being written was ignored and the request went out. Both now have tests that fail without the fix (mutations M1, M2). Plan impact: `AIService.send` (A.4) must be single-flight per request and must accept a stop at any point, including before the request leaves; M5 should keep these tests. Review round 5 found the same gap one step earlier: `createDraft` wrote a fresh draft for the pack's request ID whatever was stored, so a second call (a double tap on Ask, or the caller re-running draft then send) erased an answered record and its attempts, and reset a request already on the wire to "Draft · not sent", which a relaunch then left sendable without the confirmation an uncertain generation needs. A request ID now has one record: `createDraft` returns the existing one unchanged in any state (from memory or from the store), refuses a different pack under the same ID, and concurrent calls share one creation (M54). Plan impact: the pack's request ID is the request's identity at the A.4 boundary, and no new draft ever rewrites a record.

**F3. Substring matching mislabelled quotations as exact.** "at the end" matched inside "that the endless", and a "quotation" stitched from one-word fragments with ellipses passed. Quotation checks now compare whole tokens including punctuation, and each ellipsis segment needs three words (mutation M9). Since review round 3, letter case is compared too: until then case was ignored, so "I wished to live DELIBERATELY" was labelled an exact quotation of "I wished to live deliberately". Now only the quotation's first letter may differ in case (capitalized to start the answer's sentence, or lowercased to continue it, a standard quoting convention); any other change of case is a paraphrase (M41, M42). What is still normalized: whitespace, curly versus straight quotation marks and apostrophes, en and em dashes versus hyphens, invisible characters (zero-width spaces, soft hyphens) and Unicode compatibility forms, and punctuation at the very start or end of the quotation. The rule is stricter than "the words appear somewhere": a quotation with an added comma or a changed capital is labelled a paraphrase. That is the intended reading of plan 13.4 and I-05, and the product owner should confirm it (Q2).

**F4. "Whole book" and "Do not include later passages" contradict each other.** The earlier builder produced a pack labelled "Whole book included" holding only text up to the position. It is now refused with a message pointing to "Relevant passages from this work", and the contract rejects such a pack. Plan 13.1/13.3 should say that whole-book inclusion is unavailable under a spoiler boundary.

**F5. The vocabulary row "Asking a model" (4.4.6) has no phrases for failures, a cancel before any output, a refusal, a content-filter stop, an output limit, a reply with no answer text or a stop before sending.** What the spike shows (corrected in review round 3; until then a refusal or a content-filter stop read "Complete", even with text cut off by the filter): "Complete" only for a normal end with answer text; for a refusal or a content-filter stop with no answer text, the classified message in place of the phrase ("{host} declined to answer this question. Its reply is shown apart from answers.", "{host}'s content filter withheld the answer, so there is nothing to show."); for any stop after some answer text (refusal stop, content filter, output limit, context window, other early end), "Interrupted · partial answer" with the reason beside it (`AskRecord.outcomeMessage`); and for failures, including a reply with no answer text, the classified, actionable message. It never shows "Draft · not sent" once a request may have left the device (since review round 5 this holds for a second draft of the same request too, F2). `Packages/Design` needs keys for these states before any product UI uses them, and also for the strings added in review round 1: the coverage label "No passages sent", the five limitation disclosures, the response size and time limit messages, and the "Short quoted phrase" labels; and for the strings added in round 2: the connection test's conformance messages, the "may or may not have been processed" server-error message, the earlier-turn disclosure and exclusion reasons, and the `[earlier source]` marker; and for the strings added in round 3: the refusal and content-filter messages above, the reasons shown beside "Interrupted · partial answer", the no-answer-text messages ("{host} sent only its reasoning and no answer text …", "{host} ended its reply without any answer text …", "{host} reached the maximum output … before any answer text …", "{host} stopped before sending any answer text.") and the transcription message after a relaunch mid-upload ("Sylvia closed while this clip was being sent. It may have reached {host} …"); and for the strings added in round 4: a refusal that sent no text ("{host} declined to answer this question and gave no reply to show."), the neutral "No answer" a failed record shows if it ever lacks a classified failure, the key-for-another-address message ("The key stored for this provider was entered for a different address, so Sylvia won't send it to {host}. Enter the key for this address in provider settings."), the disclosure's counted phrases ("N selected passages", "N nearby passages", "N retrieved passages", "the whole text of {title} (N passages)", "N saved thoughts you selected") and the confirmation a resend of an uncertain transcription needs; and for the string added in round 5: the exclusion reason for earlier turns from another edition ("Earlier answers in this conversation used passages from another edition, which Sylvia can't compare with your position, so they weren't sent."). Whether a refusal with no text should have its own phrase in the row is a design question (Q4).

**F6. Local Network denial is detected through an undocumented error key.** URLSession attaches the network path to the error under `_NSURLErrorNWPathKey`; the classifier reads `unsatisfiedReason == .localNetworkDenied` from it. Host tests can only simulate this. If iOS does not attach the path, denial will show as "offline" (checklist step 2 checks this). Before M5, replace it with a documented probe (`NWPathMonitor` or an `NWConnection` attempt on failure).

**F7. The data-protection Keychain cannot be tested from an unhosted SwiftPM test bundle on the simulator** (errSecMissingEntitlement, -34018). Keychain tests run hosted in the probe app; the app targets in M1 need the same arrangement.

**F8. OpenAI stores Responses by default, and documents timestamps for `whisper-1` only.** The OpenAI adapter always sends `store: false`; transcription timing is a per-endpoint capability, never inferred from a model name. The generic adapter does not send `store` because compatible servers may reject unknown fields, so pointing the generic adapter at `api.openai.com` would use OpenAI's default retention (open question Q3).

**F9. Spoiler boundaries have paragraph granularity.** Positions are extracted-paragraph ordinals. When an oversized paragraph is split into chunks, all pieces share its ordinal, so later sentences of the selected paragraph itself can be retrieved. Retrieval never crosses into a later paragraph.

**F11. Untrusted numbers crashed the app (found in review, fixed).** A `Retry-After` value too large for a 64-bit integer, sent on any error response by any endpoint (including a LAN host), trapped in a Double-to-Int64 conversion; a transcription segment time of `1e300` trapped the same way. Retry-After now accepts only delta-seconds digits or an HTTP date and is clamped to one day; segment times that are not finite, negative, backwards or past the clip are dropped and counted. Plan impact: M5 code that converts any number from a provider must use checked conversions; the hostile-number tests should move with the adapters.

**F12. A selection after the confirmed position leaked later text into a restricted pack (found in review, fixed).** The builder filtered retrieval, nearby text and thoughts but added the selection itself without comparing it to the boundary, and still labelled the pack restricted. It is now refused with a message telling the user to move the position or turn the setting off, and a final check in the builder and the coordinator refuses any pack holding text after its own boundary. Plan 13.3 should say what happens when a selection lies after the confirmed position.

**F13. URLRequest's timeout is an idle timeout, and URLSession can hold back a small trickled body.** A server that trickles bytes, or that sends fewer than about 512 bytes of a JSON body slowly, never trips the idle timeout and delivers nothing to the app to check against a deadline (content sniffing waits for more bytes). Every response now has a wall-clock limit enforced by a timer as well as per chunk, and a size limit (see ADR-0011, "Bounded responses"). Plan 14.5's output caps need these values confirmed for M5.

**F14. The connection test passed routes that never answered (found in review round 2, fixed).** It failed only a stream with no final event or an empty normal end, so a gateway route that answered with a tool call, a refusal, or reasoning that ran into the 16-token probe limit was reported as "Test reply received". The connection test is the only conformance check the app runs (plan 14.1 makes a gateway usable only if its route passes), so it now passes only a normal end with answer text, and the probe uses the configured maximum output (default 1,024, the reserve real questions get) so models that reason first can reply. Plan impact: M5's provider settings must show these failures as "not usable", and the maximum output is part of a route's configuration.

**F15. Earlier turns of a conversation were sent without consent or disclosure (found in review round 2, fixed).** Earlier questions and answers were resent verbatim, but consent and the disclosure looked only at the current evidence, so an answer built from the user's notes could reach a newly approved destination under source-text-only consent while the disclosure said nothing else was sent. Each turn now records what it shared and where it went; a turn is resent only to the same destination (origin, classification and model) and otherwise left out with a stated reason; included turns count towards consent and are named in the disclosure. Plan impact: plan 13.1/14.2 should say that switching provider or model starts the new destination without earlier turns (or asks to resend them, a product decision: Q8).

**F16. Citation IDs restart at `c1` in every pack (found in review round 2, fixed).** Earlier answers were resent with their `[cN]` markers, which then pointed at the new pack's evidence. Markers in resent answers become `[earlier source]` (template `sylvia-grounded-3`), and the contract rejects a resent answer that still has one.

**F17. "5xx" is not one acceptance class (found in review round 2, fixed).** A gateway's 502 or 504 means an upstream may already have accepted and billed the generation, and any user-managed endpoint may be a gateway. Only 503 and 529 from a hosted or local endpoint are retried automatically; every other 5xx is uncertain and needs the user's confirmation. Plan 14.4 lists 5xx as retryable and also forbids replaying uncertain generations; this is the reading that satisfies both (Q8).

**F18. A reply with no answer text was stored as a complete answer (found in review round 3, fixed).** A stream that ended normally after only reasoning fields, only a `<think>` block, or only `data: [DONE]` became state `complete`, outcome `answer`, status "Complete" with an empty answer, although the connection test already failed such a reply (F14), and reasoning models with a tight output budget are likely to produce exactly that. Any final event with no visible answer text (whitespace counts as none) is now never an answer: a normal end, an output limit or an early end becomes `failed_retryable` with a message saying what happened and that models that reason first may need a larger maximum output; a context-window stop becomes `failed_final`; acceptance is uncertain in each case (the generation may have been billed), so a resend needs the user's confirmation and reuses the record. Plan impact: plan 14.4 should say that "complete" requires answer text.

**F19. Refusal and content-filter stops read "Complete", including text the filter cut off (found in review round 3, fixed).** A content filter omits content, so text before a `content_filter` stop is truncated, and text before an Anthropic `refusal` stop is cut off where the classifier stopped it; both were shown as "Complete". After some answer text, both now end `interrupted` ("Interrupted · partial answer", with the reason beside it and never resent without confirmation); with no answer text they end `complete` with outcome `refusal` or `content_filtered` and show their classified message, never "Complete" (F5). A host test that allowed "Complete" for these outcomes now asserts the honest label for each finish reason.

**F20. The transcription offline queue lived only in memory (found in review round 3, fixed).** The text path persisted drafts, but a queued clip, its configuration and its audio consent were lost on relaunch. The queue is now written at every state change (see B8). Two rules came with it: a clip found in `sending` after a relaunch may have reached the server, so it becomes a failure that says so and is never resent automatically (the same rule as uncertain text generations); and audio consent is checked again when a queued clip is sent, as text consent is, so a stored job can never upload without consent on record.

**F21. A stored key followed whatever base URL its configuration held (found in review round 4, fixed).** Credentials were origin-scoped only in transit (redirects blocked, the header set for the configured origin), so editing a configuration's base URL, or importing a configuration that named an existing key, sent that key to the new host, and the connection test did so with no consent step. The origin is now part of the credential reference and of the Keychain item's identity, and the providers send a key only to a request for that origin; otherwise the request stops before it leaves with "enter the key for this address". Plan impact: M5's provider settings must ask for the key again when an edit changes the origin (`ProviderConfig.credentialMatchesOrigin`), and an export or import of configurations carries the reference with its origin, never a key.

**F22. A second Transcribe request for a clip uploaded it again and could replace its transcript (found in review round 4, fixed).** `send` was single-flight but `request` overwrote any existing job, so a double tap uploaded (and may have billed) a clip twice, and a request after completion replaced the raw transcript and the user's correction. A clip now has one job: a second request returns it, and a finished transcript is never replaced; re-transcribing with earlier transcripts kept as revisions (plan 11.1) is an M5 feature. A failed upload whose acceptance is uncertain is now stored as needing confirmation and resent only with it, as on the text path; until round 4 a plain Send resent it although its message said Sylvia would ask first. Plan impact: `TranscriptionService` (A.4) must be single-flight per clip, like `AIService.send` (F2). Review round 5 found a race in the opt-in reconnect loop: it listed the queued clips once and then awaited each upload, so a clip the user sent meanwhile made the loop throw (later queued clips were never sent and the caller lost the finished results), and a clip whose user send failed with a certain error such as a 429 would have been uploaded again by the policy. The loop now checks the policy and each clip's state again just before sending it, with no suspension point in between, skips a clip that is no longer queued, and never stops at one clip's error; a clip whose `sending` state could not be saved is not uploaded and keeps its state (M55).

**F23. Saved thoughts in a restricted pack lost their place (found in review round 4, fixed).** The builder filtered thoughts beyond the boundary, but a kept thought became evidence without a position, so the self-check, the coordinator and the contract check could not see a later thought in a hand-built or regressed pack, and the stored pack could not show that a thought lay within the boundary (plan 11.2). A thought on the pack's work now keeps its work and place, and every item from the work must carry a position under a boundary (a thought whose place is not in this edition's text is left out of a restricted pack). The disclosure also counted saved thoughts as passages from the book and called retrieved passages "selected"; it now counts each kind apart. **The rule since review round 5:** paragraph ordinals count one edition's extracted paragraphs, so a position is compared with a boundary, and recorded in a pack, only in the pack's own edition. A saved thought carries the edition it was captured in (`SavedThought.editionID`); it gets a place in the pack (`position`, `edition_id`) only when that is the pack's edition and its ordinal is in this edition's text. A thought on the work captured in another edition (or with no ordinal) has an unknown place: a restricted pack leaves it out, as it does an ordinal missing from the index, and an unrestricted pack keeps it on the work with no position and no edition, so the stored pack never claims this edition's href or ID for it. Until round 5 the builder read any thought's ordinal against this edition, so a later passage of another edition with a smaller ordinal passed the filter and was stored as lying within the boundary. Earlier turns had the same gap and now carry the edition their `max_evidence_ordinal` counts in; a restricted pack leaves out a turn that used another edition, with its own reason. The self-check, the coordinator, the schema (`edition_id` with every position, and on every turn that used evidence) and the Python rule refuse a position or an included turn from another edition (M56-M58). Plan impact: M5 captures and AI turns must record the edition their anchor counts in; a boundary across editions needs the alignment plan 13.3 describes.

**F10. Token counts are estimates.** No tokenizer is bundled; the estimator (UTF-8 bytes ÷ 3) over-counts English on purpose, and every pack says `estimated: true`. Unknown models get an 8,192-token context. Exact counting needs a per-provider tokenizer or a token-counting endpoint, both optional per plan 14.1.
