## What the checker does

`Scripts/check-spike-anchors.py` adds what JSON Schema cannot show (`Scripts/validate-contracts.py` remains the schema check):

1. **Related contracts and patterns.** The capture kinds the schema knows are exactly the ones `Contracts/design/marginalia.v1.json` maps one-to-one onto the five capture markers, and that mapping renders an unknown kind as Pending, never as Quote. A saved answer's endpoint has exactly the context-pack contract's provider kinds and classifications, and the provider-config contract's kinds are exactly those three and the transcript's one. The secret-name pattern is the context-pack one written without `(?i)`. Every `pattern` in every contract schema and OpenAPI document compiles in Python and as ECMA-262 with the `u` flag, two recorded exceptions apart. The checker reads its own kind lists from the schemas.
2. **Fixtures.** Every valid fixture passes the code-checked rules U1, A1-A7 and C1-C9 (ADR-0016 section 5) and, unless it is named for a later writer, the v1 writer profile (known kinds only). Every invalid fixture is its base with the listed operations and fails with exactly its listed schema errors; every semantic-invalid fixture is schema-valid and breaks exactly its named rule once. A schema error is identified by its keyword, instance path, schema path (with `allOf` members written by their `title`, for example `allOf[typed-quote-has-no-reader-anchor]`) and, for a missing property, its name.
3. **Spike output.** G0.1 EPUB, G0.1 PDF and G0.4 output is adapted into the contract and validated against the schemas, the code rules and the writer profile. The adaptations are only renames (`version`, `asset_digest`, `reader_locator`, `saved`, G0.4's kind `audio`), removing nulls, lowercasing IDs, and supplying what a spike does not record (IDs, digests computed from the files, a source snapshot, the capture wrapper around G0.1's bare anchors, G0.4's revision from the counted writes, G0.4's clip offsets from the order its exporter writes the ranges in). Nothing a spike recorded is changed, every adaptation is counted in the report, and a record the adapters cannot read (an origin G0.4 does not write, for example) fails the check with a named error.
4. **G0.5 recovery.** Every capture row of the committed `library-v1.sqlite`, and every note row without a capture on a whole work, is mapped field by field into an envelope. What the persistence spike does not store is filled with a placeholder named for its recorded deviation; the envelope must then be schema-valid, and every code-rule violation must be a recorded deviation. The table definitions are read for the deviations rows cannot show. An observed difference that is not recorded fails, and so does a recorded one that is no longer observed.

## Findings

**F1. An earlier draft of this contract used kind strings the design package does not recognize.** The draft named the capture kinds `quote`, `note`, `audio`, `generated` and `word`, following G0.5 recovery's table. The merged design package (G0.6) resolves `text_quote`, `note`, `audio_capture`, `generated_answer` and `word`, matched exactly, renders every other string with the Pending marker, and has a test asserting that `quote` is not recognized. Every quote, audio capture and answer written to the draft would have been shown as Pending. The contract now uses the design package's strings (`text_quote` is A.1's own value), and the checker compares the two on every CI run (negative control: an export still mapping `quote` fails).

**F2. EPUB `text_offsets` locate the selection with its whitespace collapsed, not `exact_text` itself.** The G0.1 adapter (`CaptureBuilder.offsets`) collapses whitespace in the rendered selection before it looks for it in the extraction. A selection that starts or ends on a space, or spans a run of whitespace, therefore has offsets shorter than `exact_text`; a rule that counted `exact_text`, as the G0.1 envelope proposal's "where exact_text sits" reads, would refuse such a capture. None of the nine real EPUB anchors (all of which have offsets) has such whitespace, so they could not show this. The rule follows the adapter (fixture `epub-selection-starting-at-a-space.json`, constructed from the real Greek sample, and its semantic-invalid twin, which counts the space). The spike's matching also uses Foundation's `range(of:)`, which treats canonically equivalent text as equal, and collapses whitespace by grapheme clusters; M3 should match scalar for scalar (ADR-0016 open items).

**F3. Timestamps cannot be a validity rule.** The draft required `created_at <= updated_at` and `trashed_at >= created_at`. Records are stamped from the device's wall clock (G0.4 `Date()`, recovery `nowMillis`), which can move back, so a valid record would have been refused, at restore as much as anywhere. The rule is gone; revisions give the order, and a valid fixture shows a note edited after the clock went back.

**F4. No spike records asset digests for audio, and G0.1 records none of the IDs an anchor needs.** G0.4's capture record has no digest (ADR-0006 says so); G0.1's anchors carry fixture labels or fixed IDs and no Work or Edition. The contract requires them (plan 7.5). The importer (M2) and the capture transactions (M3, M4) must compute and pass them; the probe shows the values exist (the member files' digests equal the fixture generator's manifest).

**F5. The spikes disagree on small things that would break a shared format.** `asset_digest` against `asset_sha256`; `version` against the README's `schema_version`; `null` against an omitted field; uppercase against lowercase UUIDs; `saved` against `preserved` for an excerpt; four sets of kind strings (A.1, recovery, G0.4, the design package); the timeline revision on G0.4's record, on ADR-0006's proposed excerpt record or in the anchor. ADR-0016 section 8 fixes one form each, with the reason.

**F6. G0.4 keeps bookmarks in its capture store.** Plan 4.4.5 has no bookmark marker and 10.2 calls a bookmark a position only, so the envelope excludes it. Whether a bookmark with a note appears in Thoughts is an open question for M4 and design.

**F7. G0.5 recovery stores captures differently from the envelope in 37 recorded ways.** The first round claimed four, then 28 after it mapped every capture row field by field; the second review found nine more in the table definitions and the note rows (R2-04; F27). The ones that matter most for M1: the EPUB locator keeps the selected text only as a digest (which equals the quotation's) and Readium's locator without the adapter's name or version; the PDF locator has none of v1's text, extraction, page box, context or page-text digest; the word's EPUB anchor has only a resource and two offsets; `capture_anchor.edition_id`, and `asset_id` for every kind except audio, may be NULL; the excerpt row has only a duration, names its ranges by digest, requires a blob in every state (pending and failed included), records no failure reason or attempts, is not unique per capture, and has no removed state; nothing stores a transcript; a generated capture has no link to its conversation, message or context pack, and a message has no cancelled state; the CHECKs let a note or a generated capture hold quoted text and a word lack it; an audio anchor keeps the member's position, which a reorder would make stale; and the capture revision ignores the excerpt. One row is inconsistent in itself: the golden PDF quotation's `text_range` `[880, 939]` covers 59 scalars for a 60-scalar quotation, an inclusive end or an off-by-one, where its EPUB anchor's half-open range matches (`GoldenCorpus.swift` computes the EPUB end from the quotation and writes the PDF range as a constant). ADR-0016 section 8.3 now says what its table covers: every difference between a row and its envelope, and every per-row constraint or column that admits what the envelope refuses or lacks what it requires; rules the envelope checks across records in code (C1, C3, C6) are not expected of the tables. Recovery's locator JSON is fixture data, not reader output, which is why several anchors are reduced; its table shapes are what M1 starts from.

**F8. G0.4 can call an excerpt saved when the contract would not call it preserved.** `AACExcerptExporter` returns `outputDurationMs: nil` when AVFoundation cannot read the written file's duration; checks only the total frame count, so a range that decoded to no samples gives an empty actual range; records `byteCount` 0 when the file's size cannot be read (`?? 0`); records the decoder's start without comparing it with the requested range; and never compares the read-back duration with the frames it wrote. On failure it records `"\(error)"`: `ExportError.decodeFailed("\(segment.url.lastPathComponent): \(error)")` and `encodeFailed("\(error)")` carry an AVFoundation error description, which can include a file URL or path and is unbounded in length (the contract allows 2,000 characters); G0.4's `5f4be95` adds `encodeFailed("file protection: \(error)")`. The contract refuses each as a preserved excerpt (rules C4 and C9, `duration_ms` and `byte_count` bounds) or as a failure reason (negative controls for the missing duration, the empty range, a range from elsewhere, a range that overlaps its request by 1 ms, a 1 ms read-back, a path and a UNC path). Until round 2, C4 asked only that an actual range overlap the requested one, so an excerpt overlapping it by 1 ms was accepted although this finding said the contract refused an unchecked actual start (R2-02); C4 now bounds the start and end by plan 19.2's 500 ms (F26). The probe's exports read back 30,000 ms each, have actual ranges equal to the requested ones, and pass every rule, at `943d5e7` and at `5d85b1f`.

**F9. A range edit can orphan a preserved excerpt.** `CaptureService.setRange` returns the excerpt to pending; the earlier file stays on disk until a new export replaces it, but the record no longer refers to it. If the source has been removed, every re-export fails ("source not on this device") and the only audio is unreferenced. This is G0.4 behavior, not a contract change; M4 decides whether the previous excerpt stays referenced until a new one is preserved.

**F10. An AAC excerpt is not byte-reproducible.** Probe runs of the same ranges produced files of identical size (295,185 and 288,429 bytes) with different SHA-256 values (this run's `context.json`, the earlier run's at commit `7b239b1`, and both runs of the head check). A blob digest identifies one export; a retry or re-export always gives a new blob, and a transcript of the earlier clip stops matching (rule C5).

**F11. PDF details the G0.1 builder leaves to PDFKit.** Its `exact_text` is PDFKit's `selection.string`, which equalled the segments joined with U+000A (ADR-0005's definition, rule A3) in all ten samples; its line rectangles are not clamped to the CropBox; and a range PDFKit draws no line box for would give a segment without rectangles. The contract requires the join (A3), rectangles within the page box (A7: x + w <= 1 and y + h <= 1, each edge with its own fixture now) and at least one rectangle per segment. All ten real samples lie inside the box (largest x + w 0.849077, largest y + h 0.968347). M3 builds or verifies each.

*Corrected on 19 October 2026 (M0 final review, evidence R1-02 and contracts R1-01):* the join was not ADR-0005's definition. This work read the G0.1 PDF branch before its round 4, whose builder and ADR-0005, merged at M0 assembly after these contracts, define `exact_text` as PDFKit's composition of a selection's pieces and ask the schema not to define it as a join (ADR-0005, PDF anchor envelope and open items; `G01-PDF.md` finding 15 and open question 4). Six of the eleven composed selections the spike stores exactly broke the old A3, which CI did not show because none of the ten samples was composed. A3 is now that composition: the segments in order, with nothing or one U+000A between two on one page and one between pages (ADR-0016 sections 5 and 11); the spike's composed anchors are checked as spike output and give three valid fixtures (`evidence/M0-Integration/final-fix/a3-composed-check.log`). Owner after M0: M1, with M3 (`Contracts/README.md`).

**F12. The context-pack contract accepts uppercase UUIDs.** This contract and `backup-manifest` accept only lowercase. A `capture_id` written by Swift's `uuidString` would compare unequal across them; M5 decides (ADR-0016 section 9).

**F13. The design vocabulary has no machine-transcription caveat.** Plan 10.4 requires machine transcription to be labelled as potentially inaccurate. G0.5 shows "Machine transcription · may be inaccurate" from its own record; the design package has only "Transcript" (`audio.transcript`). The envelope stores no label.

**F14. "One reason per invalid file" was claimed in the first round but not checked, and was false for three fixtures (R1-01).** The checker only asserted that an invalid fixture failed. Now each fixture lists its exact expected errors and the checker compares them; the three masked fixtures are rebuilt with the origin added or removed alongside, and constraints that other rules already implied were removed rather than tested twice. The second round showed the mutation pass built then still missed weakenings (F25).

**F15. A typed quotation could sit at a reader anchor whose text differs (R1-02).** The `text_quote` rule allowed `quoted_text_origin: user_entered` with any EPUB, PDF or text anchor, and rule C2 compares a quotation with its anchors only for a selection, so a v1 client would have shown typed words with a highlight on another passage. The rule `typed-quote-has-no-reader-anchor` refuses it; a typed record has no reader anchor, and a correction of a selection keeps its origin (an additive field later, ADR-0016 open items).

**F16. The excerpt had no state for an excerpt the user removed and no clip-local offsets (round-1 gate gaps).** Plan 10.2 and 17.2 let the user remove excerpt audio separately; without a state, a writer would have had to drop the required excerpt record or call it pending, which G0.4 re-exports at launch. The envelope has `removed` (the record of the export stays, so a transcript quotation stays valid; the file does not). Plan 7.2 lists clip-local offsets: each actual range has `clip_start_ms`, and rule C9 checks that the excerpt is the ranges back to back.

**F17. The failure-reason guard is a heuristic, and round 2 found paths it let through (R1-05, R2-07).** Round 1 replaced a pattern that refused "unsupported profile" and missed drive paths. Round 2 found that `path>/private/var/x`, a UNC path (`\\server\share\...`) and a home path with its leading slash dropped were allowed while the description said such paths never were. The guard now also treats `>`, `|` and a backquote as word starts and refuses a leading `\\`; the schema and ADR-0016 section 4 call it a heuristic and list what it lets through (a path after another character, a dropped leading slash, another user's home, a percent-encoded URL); `check-patterns.py` shows those allowed and 20 path forms refused, the same in Python and node; and the decision that matters is upstream: M4 builds a reason from an error code and at most a bare file name, never from AVFoundation's free text.

**F18. The unknown-kind rule promised more than the schema allowed (R1-06).** "Never rejected or dropped" was not true of a later kind with a new excerpt state or provider kind, or of a capture whose only anchor has no edition. ADR-0016 section 6 states what keeps a later writer's record readable (v1-defined fields keep their definitions; four fields take new token values on an unknown kind; known anchors validate and name their edition) and that anything else needs a new field, kind or version, which v1 refuses before changing anything.

**F19. G0.4 moved on during this work (R1-08).** The probe runner compiled a fixed list of G0.4 files at `943d5e7`; from `99808ca` G0.4's capture code needs `AssetTiming.swift` and `MP3FrameScanner.swift`, so the runner compiles them when present and passes each member's import decision to `CaptureService`, as the G0.4 harness does. `check-g04-head.sh` shows it runs at `943d5e7` and at `5d85b1f` (13 files, warnings as errors) with unchanged records and timing. G0.4 then moved again (F31).

**F20. Statements in the schemas and the first ADR that nothing enforced (R1-10).** A preserved excerpt with `duration_ms` 1 for 30 s of ranges, actual ranges from elsewhere in the file, two notes with one ID, a transcript segment ending long after its clip, and a preserved or failed excerpt at revision 1 were accepted in the first round. Rules C4, C6, C7, C8 and C9, and the word's source sentence in C2, check them, each with semantic-invalid fixtures; the G0.4 output passes them all.

**F21. The context-pack contract cannot say a quotation is a corrected transcription (round-1 gate gap).** Its evidence `source_quality` has `exact_capture`, `user_entered` and `machine_transcript`, and requires `machine_transcript` with `origin` `transcript`. A `corrected_transcript` quotation therefore has no faithful value; ADR-0016 section 9 maps every other field and asks the context-pack owner (M5) for a value or a decision.

**F22. Cross-edition relocation was undecided (round-1 gate gap).** ADR-0016 section 7 decides it: the capture's `edition_id` and `anchors` are never moved or replaced, a confirmed relocation is recorded beside them in an additive field M3 defines when it builds the flow, and rule C1 keeps `anchors` to one edition by design.

**F23. No JavaScript validator could load either schema (L2-R2-01).** The secret-name pattern, applied to every property name at the root of both payloads, used Python's inline `(?i)`, which is not ECMA-262: Ajv and every validator that compiles a pattern with `new RegExp(pattern, "u")` fail on it, so no JavaScript client, server or harness could compile `anchor.v1` or `capture-envelope.v1` at all. CI did not notice because Python accepts `(?i)`, and the round-1 ECMA-262 check covered only the failure-reason pattern. The pattern now spells each letter's cases out, with exactly the characters Python's case-insensitive match accepts (İ, ı, the Kelvin sign and the long s included), and gives the old pattern's Python verdict on 292 spellings (151 refused) in Python and node alike. The checker now compiles every pattern of every contract as ECMA-262 on each CI run, with its own grammar check (no new dependency), which agrees with node on all contract patterns and 84 corpus patterns. The context-pack and provider-config contracts have the same `(?i)`; they are recorded exceptions and requested of M5.

**F24. Python and ECMA-262 still read two constructs differently.** Python's `$` also matches before a final newline, so this repository's Python-based validators accept an ID, digest or token followed by a newline (for example a secret name `key\n`) that an ECMA-262 validator refuses; and Python's `\s` includes U+001C-U+001F and U+0085 but not U+FEFF, which shifts the failure-reason guard by those characters (`check-patterns.log`, section 5). Every contract has the first; the fix belongs in the shared validator (an ECMA-262 engine for `pattern`, requested), and a writer never produces such a value. No fixture can show it until then, since `10-contracts` would call it valid.

**F25. The negative tests still missed a rule condition, two code-rule branches and integer milliseconds (R2-01).** Narrowing the transcript-origin rule's condition to `machine_transcript` let a corrected-transcript quotation stand without a transcript or with a pending excerpt; disabling C5's corrected-text comparison or A4's same-page overlap changed no outcome; and deleting `type: integer` from the millisecond definition let `start_ms` 60000.5 through, since every `type` counted as a generic bound. The mutation pass did not touch `if` conditions or the code rules, and CI did not run it. Now the pass also deletes single `enum` values in `if` conditions and inside `not` (14 sites), protects every numeric `type` (28 sites, each with a fraction or string fixture), and removes each of the checker's 60 code-rule checks, compound-check operands, revision increments and helper calls in turn; the drop-in runs it on every change. Going through every branch the pass now removes showed more gaps than the review named, each now with a fixture: a PDF rectangle reaching above the page box, a property name with an unpaired surrogate, an EPUB segment count unequal to the number of anchors, a removed excerpt or a transcript at too low a revision, an anchor rule broken inside a capture, a PDF or text quotation unequal to its anchor, and two PDF anchors on one selection. The pass's first run then showed six single kind values of the `anchor-names-edition` and `known-kind-values` conditions noticed only through the writer profile (and the pass had read the profile's kinds from the unmutated schemas, which the checker does not); the pass now reads them as the checker does, and each kind has a schema-level fixture of its own (`anchors-without-edition-id-pdf.json`, `note-kind-with-an-unknown-surface.json` and the like).

**F26. C4 accepted an excerpt that overlapped its request by 1 ms (R2-02).** See F8. Fixtures: the review's example (`c4-actual-range-overlaps-by-one-millisecond.json`) and a range starting or ending 600 ms short, each with the frame count of what it holds so only C4 breaks; negative control on G0.4's own record.

**F27. Notes without a capture: the envelope contradicted itself, and a note on a conversation has no form (R2-04).** ADR-0016 called recovery's capture-less notes "outside this envelope", while its anchors description and a valid fixture modelled a note on the whole work as a `note` capture. The decision is the latter (plan 11.1: notes may be work-level; one envelope per saved thought), with source kind `work` (`note-on-the-whole-work.json`); the checker maps recovery's two work-level notes into such captures. **F28. The Markdown text anchor left open what `exact_text` holds when a selection crosses markup (L2-R2-05, from the gate gaps).** `text_range` indexes the Markdown source while the selection is made in rendered text, so for `for *absolute freedom* and wildness` the rendered words are two scalars shorter than the range and rule A2 refused the capture, with nothing saying what a writer should store.
