**How to read a result.** Every result names its environment:

- **host:** macOS tests on the build Mac
- **simulator:** iOS runtime and device type
- **device:** physical model and OS version

**pending** means the check needs a physical device, a second device or a person, and has not been run. It is never shown as passed. Reviews done by agents in place of a security, QA or design reviewer are marked "agent-reviewed; human sign-off pending". Timings taken while other agents were building on the same Mac are indicative only and say so, with the load recorded next to them.

An "accept-with-minor" verdict is an agent review's judgment that the branch is fit to merge with its listed minor findings still open; it is not a gate pass. Each report's own result table is the gate status: many criteria are **pending-device** or **pending-human**, G0.2 records two **failed** rows (a Tailscale address and a MagicDNS name without an App Transport Security exception), G0.4 records the plan 19.2 start/resume budget as **failed** on the simulator for long files that stay on precise timing (rows 21 and 33: a cold resume deeper than about 1-1.8 hours into a VBR MP3, and native FLAC and MP3-without-header files beyond a length limit), with quick capture and the shippable-workflow recommendation **partial**, G0.6 records type scaling through `UIFontMetrics` as plan 4.4.3 specifies as **failed** (up to 6.3 pt off the system sizes; its approach changed), and G0.1 PDF records the highlight overlay on text drawn with rotated text matrices as **failed** (row 10c; the anchors themselves restore exactly; plan draft 0.7 proposes its approach change, A54). *(The last two added on 19 October 2026: this sentence named only G0.2 and G0.4; `M0-gate.md` Section 6.3.)*

An agent review's "accept-with-minor" on an `m0-int-minors-*` branch accepts the fixes of the findings named above; any minor findings that review raised stay with the gate, and the fixes are agent-reviewed, human sign-off pending.
