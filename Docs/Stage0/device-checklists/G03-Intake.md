# G0.3 intake: physical-device checklist

Everything here is **pending** until run on a physical iPhone. Nothing below may be inferred from the simulator results in `Docs/Stage0/G03-Intake.md`.

## Setup (once)

1. Device: record model, model identifier and iOS version (Settings > General > About). Plan baseline is an iPhone 12-class device; the recorded test phone is an iPhone 17 Pro on iOS 26.7 (ADR-0001). Run on both when available.
2. Free space: at least 25 GB (Settings > General > iPhone Storage). Record the free space shown.
3. Build and install. `project.yml` signs for the simulator only (`CODE_SIGN_STYLE: Manual`, ad-hoc identity `-`), which a phone cannot run, so device builds override the signing settings:
   - Xcode: on the Mac, from the repository root, `source Scripts/lib/env.sh; source Scripts/lib/xcodegen.sh; sylvia_generate Spikes/G03-Intake/App`, open `Spikes/G03-Intake/App/G03Intake.xcodeproj`, and for **each of the four targets** (IntakeHarness, IntakeShare, IntakeHarnessTests, IntakeHarnessUITests) open Signing & Capabilities, turn on "Automatically manage signing" and choose team A4KBDX665Z. Automatic signing registers the App Group `group.com.jevidon.sylvia.spike` for the app and the extension. Run the IntakeHarness scheme on the phone.
   - Command line (used by step 24): find the phone's identifier with `xcrun devicectl list devices` (use the Identifier only when it is the device's UDID, copying the identifier alone; if devicectl shows an ECID or a CoreDevice identifier instead, take the UDID from Xcode > Window > Devices and Simulators > the device > Identifier: `xcodebuild -destination id=` needs the UDID), then
     `xcodebuild test -project Spikes/G03-Intake/App/G03Intake.xcodeproj -scheme IntakeHarness -destination 'id=<device id>' -derivedDataPath Spikes/G03-Intake/App/.build/DerivedData-device -disableAutomaticPackageResolution -allowProvisioningUpdates -allowProvisioningDeviceRegistration CODE_SIGN_STYLE=Automatic DEVELOPMENT_TEAM=A4KBDX665Z CODE_SIGN_IDENTITY="Apple Development" -only-testing:IntakeHarnessTests/InAppLayoutTests`
     (after `source Scripts/lib/env.sh`). Record the full command used if it differs. The second provisioning flag registers a device the team has not registered; it takes effect only with the first. It needs the team's account in Xcode (Settings > Accounts): the App Group `group.com.jevidon.sylvia.spike` is in no profile on the build Mac, and without the account the build stops with "Provisioning profile "iOS Team Provisioning Profile: *" doesn't include the App Groups capability" (`Docs/Stage0/evidence/M0-runbook/device-builds/g03-intake-tests-signed.log`).
4. Generate the large pack on the Mac: `Scripts/fixtures/generate-g03-intake-pack.sh`. It prints the pack path (`~/Library/Caches/SylviaFixtures/generated/g03-intake/large.sylviapack`, 4,846,059,727 bytes, SHA-256 `982562b0...0268`, 5 files). For step 27, also make a small pack: `(cd Spikes/G03-Intake/IntakeKit && swift run -c release sylviapack-tool gen-pack ~/Desktop/small.sylviapack "$(mktemp -d)" 1000000)`. Without extra file arguments it holds **4** files (two CAF parts, a Markdown and a text file); only the large pack gets a fifth, the LibriVox MP3.
5. Recording: for each step write passed-device or failed, the device, the iOS version, the date, the numbers asked for, and a screenshot of the extension or harness screen, into `Docs/Stage0/evidence/G03-Intake/device-<model>-<date>.md` (screenshots under 2 MB, next to it). The extension shows only counts, sizes, memory figures, protection classes and how each item arrived; the harness's drop-area list shows file names, so use only the public-domain fixtures named here and crop anything else before committing a screenshot.

## Shares from real providers

In each case the extension appears in the share sheet as **Sylvia Intake Spike** (the containing app's name). After every "Received", record the extension's "Received as:" line (representation, whether the provider handed over its original file "in place" or a "temporary copy", and the provider's type) and its "Protection:" line.

6. **Files, local file.** From the Mac put `Fixtures/epub/se-walden.epub`, `Fixtures/epub/se-meditations.epub` and `Fixtures/audio/meditations-01-first180s.mp3` in a folder in iCloud Drive; on the phone, in Files, select them there and Move them to On My iPhone. (AirDrop can hand an EPUB to an app that claims EPUB, such as Books or this harness, instead of saving it in Files.) In Files, long-press it > Share > Sylvia Intake Spike. Expected: "Received by Sylvia", "1 item(s), 997147 bytes". Tap Done, open the harness. Expected within a few seconds: the summary's `share=` count rises by 1 and the last scan line shows `accepted=1`. Record the screenshots and the "Received as:" line. Record also the time from "Received by Sylvia" to the harness's scan line with `accepted=1` (report finding F11, open question 7). (On the iOS 26.5 simulator the same share from On My iPhone arrived as `file_representation, in place`, once the harness had been launched after installation; before that, Files offered no third-party extension at all. Record whether the phone behaves the same, including whether Sylvia Intake Spike is offered before the harness has ever been opened.)
7. **Files, several files at once.** Select `se-walden.epub`, `se-meditations.epub` and `meditations-01-first180s.mp3`, Share > Sylvia Intake Spike. Expected: "3 item(s)" with the sum of their sizes; the harness imports one job with three items.
8. **Safari, downloaded file.** Download a public-domain EPUB in Safari (for example from standardebooks.org), open the Downloads list, share the file to Sylvia Intake Spike. Expected: received and imported, as in step 6. Then share the **web page** itself (Share button on the page). Expected: the extension shows "Not received. Nothing was saved to Sylvia." with the reason "offered a link or a temporary preview, not a file Sylvia can keep" and both alternatives. Nothing new appears in the harness.
9. **Mail attachment.** Mail yourself `se-meditations.epub`. In Mail, long-press the attachment > Share > Sylvia Intake Spike, once after the attachment has downloaded and once before (tap Share immediately in a freshly opened message). Expected: received when the provider supplies the file; otherwise the fallback, never "Received" without the file. Record which happened and how long the provider took. Then once more in a fresh message before the attachment has downloaded, and tap **Cancel** while the extension still shows "Zero KB copied". Expected: within a few seconds "Not received. Nothing was saved to Sylvia." with "The copy was cancelled."; nothing imported (review R2-01). Record the time from Cancel to that message.
10. **Books-like provider.** From Books, open a PDF you added yourself, Share > Sylvia Intake Spike (if Books offers it). Also try one other reading app installed on the phone. Expected: received, or the fallback with an actionable route. Record each provider's registered behaviour (received or which fallback reason).
11. **Unsupported content.** Share a photo from Photos. Expected: Sylvia Intake Spike is not offered (activation rule), or if offered, the fallback "This share did not include one". Nothing imported.
12. **An EPUB stored as a folder.** On the Mac, unzip `se-walden.epub` into a folder named `Walden.epub` (`mkdir Walden.epub && cd Walden.epub && unzip ../se-walden.epub`) and copy that folder into iCloud Drive; on the phone, wait until Files shows it. (A Mac's Books library and iCloud Drive's Books folder can hold EPUBs this way.) In Files, share it to Sylvia Intake Spike. Expected: "Not received. Nothing was saved to Sylvia." with the reason "offered this book as a folder (an EPUB stored unpacked), not as a single file" and only the "Send it from your Mac" route; nothing imported. Record what Files offered: whether Share was available for the folder at all, and whether the extension received a folder or a file (iOS may compress a package folder on the way; if it was received, record the "Received as:" line and the byte count).
13. **Open With and the share sheet's app row.** In Files, long-press `se-walden.epub` > Open With, and Share > the app row (and More). Record whether **Sylvia Intake Spike** is listed in each (the app declares EPUB, PDF, text, Markdown and audio as an alternate viewer and `.sylviapack` as owner). On the iOS 26.5 simulator, Open With showed "No Apps Available" and the share sheet's More list of apps was empty (the extension itself was offered in the share row); with `LSSupportsOpeningDocumentsInPlace` set to YES in an experimental build, Open With listed Sylvia Intake Spike (`simulator-open-with-in-place-experiment.log`). On the phone, record whether Open With lists the app with the committed value (NO); this feeds the product owner's decision on that key (ADR-0010 open items). If it is listed, tap it. Expected: as step 25.

## Large file and memory limit

14. **Large file share.** Put the 4.5 GiB `work/part-01.caf` from the fixture cache into the Files app on the phone: AirDrop it from the Mac (iOS saves files it has no app for into Files > Downloads; if asked, choose Files) and record where it landed. (Sylvia's own Documents folder is not visible in Files, by design: report finding F6; step 19 checks it.) In Files, share it to Sylvia Intake Spike and keep the sheet open. Expected: progress counts up; "Received by Sylvia" with "4831838986 bytes"; the harness imports it. Record: elapsed time, the extension's "Extension footprint: start ... peak ..." line, the "Available before the memory limit at start" figure, the footprint series line and the "Received as:" line, and the time from "Received by Sylvia" to the harness's `accepted=1` scan line.
15. **The memory limit itself.** From step 14's screenshot: limit ≈ start footprint + available-at-start bytes (the extension shows both `os_proc_available_memory` and `task_vm_info.limit_bytes_remaining`; os/proc.h says the former returns 0 for a process that is not an app, so use the latter if they differ, and record both). Record this number for each device model. Expected: peak footprint well below it (the simulator peak was about 50 MB; the simulator enforces no limit).
16. **Termination under memory pressure.** Start a 4.5 GiB share (step 14). While it copies, switch to Camera and record 4K video for a minute, then open several large apps, then return. Expected: either the share completes ("Received", imported), or the extension is gone (sheet disappears or shows an error) and the harness, opened afterwards, shows `inProgress=1` and **does not** import anything; after an hour (or after the clock advances an hour) a scan shows `removed=1`. "Received" must never appear without the import following. Record which outcome occurred.
17. **Force-quit mid-copy.** Start a 4.5 GiB share; while copying, swipe up to the app switcher and dismiss the host app that presented the share sheet. Expected: as step 16's failure branch; nothing imported, nothing claimed.

## iCloud placeholder

18. **A download that takes longer than the 60 s stall limit.** The extension gives up only when the provider's progress stops moving for 60 s (ADR-0010 section 1; on the host, the loading Progress reports a provider's progress through `fractionCompleted` only, which the extension watches). Whether an iCloud download reports its progress there is what this step checks.
    - Put the 4.5 GiB `part-01.caf` in iCloud Drive from the Mac and let it upload. On the phone, make sure it is not downloaded (cloud icon; long-press > Remove Download if needed). If the phone's network downloads 4.5 GiB in under 60 s, use the Network Link Conditioner (Settings > Developer) with a profile of about 50 Mbps or slower, and record the profile.
    - Share it to Sylvia Intake Spike and keep the sheet open. Expected: the extension waits while iCloud downloads (its byte counter may stay at 0 while iCloud downloads, then counts up during the copy) and then shows "Received" with "4831838986 bytes", well after 60 s. Record the time from tapping the extension to "Received", and the "Received as:" line. **FAIL** if "Not received ... stopped sending the file before it arrived" appears while the download was still progressing (that would mean iCloud's progress does not reach the extension, and the stall limit cuts off live downloads).
    - Repeat with a not-downloaded file in Airplane Mode. Expected: the fallback "stopped sending the file before it arrived" about 60 s after tapping (or a provider error sooner), never "Received". Record the outcome and the time.
    - **Cancel while iCloud is still downloading** (review R2-01). Make the file a placeholder again (Remove Download), share it, and about 10 s after tapping Sylvia Intake Spike, while the counter still shows "Zero KB copied", tap **Cancel**. Expected: within a few seconds "Not received. Nothing was saved to Sylvia." with "The copy was cancelled."; Done closes the sheet; the harness, opened afterwards, imports nothing (`share=` unchanged). **FAIL** if the sheet stays on "Copying to Sylvia…" after Cancel. Record the time from Cancel to the message, and whether the download in Files stopped or went on (the extension cancels its load; on the simulator that cancel did not reach the sharing app's own provider within the test, `sim-app-tests.log`, so whether it stops an iCloud download is what this records).

## Finder cable copy of a bundle above 4 GiB

19. **Only the drop area is visible.** Connect the phone to the Mac with a cable, unlock it, trust the Mac. In Finder select the phone > Files tab. Expected: **Sylvia Intake Spike** is listed and shows only its Documents folder contents (empty at first). No `Library`, database, journal, `handoff.json` or staging files are visible. Then, on the phone, open Files > Browse > On My iPhone. Expected: **no** "Sylvia Intake Spike" folder (finding F6: with `LSSupportsOpeningDocumentsInPlace` = NO, Documents is not exposed in the Files app). Record both screenshots.
20. Drag `large.sylviapack` onto Sylvia Intake Spike in Finder and wait until Finder finishes. In the harness, pull to refresh. Expected: the drop area lists `large.sylviapack` with 4846059727 bytes and kind `bundle`. Tap Import. Expected: "Imported large.sylviapack: 5 files, state staged, route documents_bundle" (or `needs_review` if those bytes were imported before), and the bundle then disappears from the drop area in the harness and from Finder's Files tab (imported bundles leave Documents, ADR-0010 section 5). Record the elapsed time and the free space before and after.
21. **Partial copy while Finder is still copying.** Drag the bundle again, and while Finder's progress is below 50 % switch to the phone and tap Import as soon as the file appears in the list. Expected: "Not imported: bundle rejected: truncated_or_not_a_pack ..." and no new job; the partial file stays listed. After Finder finishes, tap Import again. Expected: imported (`needs_review`, the same bytes as step 20), and the bundle leaves the drop area.
22. **Cancelled copy.** Drag the bundle again and cancel the copy in Finder midway. Record what remains in the drop area (no file, or a partial file with its size). Tap Import on anything listed. Expected: rejected; no job created; the file stays until removed. Remove it with the harness's Remove button and confirm Finder no longer shows it.
23. **Finder delete does not touch the catalog.** Drag the bundle again and do not import it. Note the harness summary's job counts, delete `large.sylviapack` in Finder, pull to refresh. Expected: the drop area is empty and the job counts are unchanged.
24. **Data protection and backup classes.** This test run includes `InAppLayoutTests/finderDeletion`, which deletes everything in the harness's Documents folder: run it after steps 19-23, with nothing in the drop area that you still need. Run the in-app layout test on the phone (step 3's command line) and record its `G03-EVIDENCE layout: protection attributes (device): ...` line and its `excluded from backup` line from the xcodebuild output. Expected: `NSFileProtectionCompleteUntilFirstUserAuthentication` for every entry: `library.sqlite`, `library.sqlite-wal`, `library.sqlite-shm`, `Staging/`, `Staging/journal.json` (present once any import has run), `Knowledge/Notes/`, `Media/`, the App Group `Intake/Handoffs/` inbox, the handoff directory, `handoff.json` and the handoff item; `Staging=true handoffInbox=true` excluded from backup. Also record the `G03-EVIDENCE layout: clone protection (device): ...` line: it shows which class an APFS clone gets when its source has a different class (open-in and drop-area imports keep a clone of the source, and clonefile(2) copies the source's attributes). Expected for the plan: `clone=NSFileProtectionCompleteUntilFirstUserAuthentication` (the staging directory's class). If the clone instead keeps the source's `NSFileProtectionComplete`, record that as a finding, not a pass: background work could not read such a staged item while the phone is locked, so the importer would have to set the class on each clone. Also record the extension's own "Protection:" line from step 6 (what the extension process wrote: inbox, handoff directory, `handoff.json`, items). Expected: the same class. Any entry with a weaker class (`NSFileProtectionNone`) or with no attribute is a FAIL.

26. Expected: as step 25. Repeat with the same file. Expected: `needs_review` (duplicate), never a second `staged` job.

## Raw files copied with Finder, and Import from Files (plan 8.1, 8.5; review R2-05)

The simulator covers both routes in `sim-app-tests.log` (ImportRoutesUITests): a raw file placed in Documents by the harness, standing in for Finder's copy, and the system document picker picking from On My iPhone. A real Finder copy and iCloud downloads through the picker are what these steps add.

28. **A raw file copied with Finder.** In Finder's Files tab, drag `Fixtures/epub/se-walden.epub` onto Sylvia Intake Spike and wait until Finder has finished. In the harness, pull to refresh. Expected: the drop area lists `se-walden.epub` with 997147 bytes and kind `file`. Tap Import. Expected: "Imported se-walden.epub: 1 files, state staged, route documents_file" (or `needs_review` if those bytes were imported before, for example in step 6), and the file **stays** in the drop area and in Finder: a raw file is never removed automatically, because without a manifest nothing proves Finder had finished. Tap Remove and confirm Finder no longer shows it.
29. **A raw file while Finder is still copying.** Drag the 4.5 GiB `work/part-01.caf` from the fixture cache onto Sylvia Intake Spike in Finder and, while Finder's progress is below 50 %, tap Import as soon as the file appears in the harness's list (pull to refresh). Expected: "Not imported: the file changed while it was being imported (still being copied?): wait until the copy has finished, then import again" and no new job; the partial file stays listed. Record the message. **FAIL** if it says "Imported part-01.caf: 1 files, state staged" while Finder was still copying: the check saw no change between the snapshot and the end of hashing, and part of the file was staged (report finding F15). After Finder finishes, tap Import again. Expected: "Imported part-01.caf: 1 files, state staged, route documents_file". Remove the file afterwards.
30. **A cancelled raw copy.** Drag `part-01.caf` again and cancel the copy in Finder midway. Record what remains in the drop area: no file, or a partial file with its size. If a partial file remains, tap Import. Expected, and recorded as the plan 8.5 limitation rather than as a pass: it no longer changes, so it is staged ("Imported part-01.caf: 1 files, state staged ...") as the partial bytes it holds; only the later validation of the audio can catch it (F15). Record the outcome, then Remove the file.
31. **Import from Files, a local file.** With `se-walden.epub` in On My iPhone (step 6), open the harness, tap **Import from Files**, then Browse > On My iPhone > `se-walden.epub`. Expected: "Picked file staged: 1 file(s), state needs_review, 997147 bytes" (the same bytes as step 6) and the detail line "pick 1: picked from outside the app container; security-scoped access granted: true; source identity before and after the import equal (device, inode, size, modification time): true [...]; source SHA-256 afterwards equals the imported bytes: true" (the file is left untouched: its identity is compared before and after, and its bytes are hashed again afterwards; review R3-05). Any `false` is a FAIL. Pick it again. Expected: `needs_review` again, never a second `staged` job, and the same two `true` values.
32. **Import from Files, an iCloud placeholder.** Put `se-meditations.epub` in iCloud Drive on the Mac; on the phone make sure it is not downloaded (cloud icon; long-press > Remove Download). Tap Import from Files, choose iCloud Drive > `se-meditations.epub`. Expected: the file downloads first (the picker or the importer's coordinated read waits for it; record how long, and whether a progress indicator shows), then "Picked file staged: 1 file(s), state staged, <size> bytes" with "security-scoped access granted: true" and "source SHA-256 afterwards equals the imported bytes: true" (`false` is a FAIL). Also record the "source identity before and after the import equal" value and the identity in brackets: when iCloud materializes a placeholder during the import, its size or modification time may legitimately change, so a `false` here is an observation to record (with whether the size before was the full size), not a failure. Repeat in Airplane Mode with another not-downloaded file. Expected: the picker refuses it, or "Picked file not imported: ..." appears; never `staged`. Record which, and record it as a finding if the harness stays on "Importing picked file…" for more than a minute (the importer has no time limit or Cancel for a coordinated read that waits on a download).
