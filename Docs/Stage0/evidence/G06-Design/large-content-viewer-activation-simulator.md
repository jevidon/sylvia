# Large content viewer: a long press activates a control exactly once

Environment: simulator (iPhone 17; model iPhone18,3, iOS 26.5). Generated by `AreaNavigationTests.testLargeContentViewerActivatesControlsOnce` on the player's Play/Pause button (XCUITest `press(forDuration:)`). The button toggles, so a missed activation and a double one both leave the label unchanged; each row waits 0.5 s more for a late second activation. The 0.15 and 0.2 s presses (review round 3) are shorter than the 0.25 s at which the lift recognizer used to begin, and longer than the viewer's own delay at AX5. The last row of each text size is a 3 s press immediately followed by a tap at the same point (review round 3, R3-02): the tap is a new touch and must toggle again, so the label returns to where it was; the time is from the end of the press to the return of XCUITest's tap, an upper bound on when the tap's touch began. The case where the Button's own action arrives after the lift activation (a busy main thread) cannot be produced reliably here; the gate's handling of it is proven by the unit tests `liftActivationEitherOrder` and `liftActivationLimits`.
