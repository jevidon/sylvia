# Security advisory search for the pinned packages and the code they ship (ADR-0014)

Four searches by the M0 dependency-lock agent, reading public advisory sources only. Nothing from this repository's code, documents or fixtures was sent anywhere: the queries are public package, project and version names, taken from public lockfiles, registries and file headers. The results are what those sources listed at the time. "None found" means none was listed in the sources named, not that none exists.

1. **12 October 2026, 19:25 to 21:10 UTC, by hand** (13 October in New Zealand): the GitHub Advisory Database and OSV.dev web pages, for the 23 Swift packages and the components they vendor, each hit checked against the pinned source. Method and the tables from "Advisories that name a pinned package" onward.
2. **13 October 2026 (UTC), version-exact, scripted** ([`advisories-search.log`](advisories-search.log), written by `commands/advisories-search.py` from `commands/run-all.sh`; first run that morning, repeated for review round 2 with the final tree, the log being the latest run): OSV's API and the GitHub Advisory Database's API, at each package's exact version, for the npm packages and Hypothesis code inside Readium's navigator scripts, the 23 Swift packages again, the CI Python tools and pip, and the two workflow actions. pip is asked at two versions: the shared virtualenv's 26.2.1, and 26.1.2, which a freshly bootstrapped virtualenv holds (review R2-01). Each ecosystem carries a positive control, so an empty result means "none listed", not "nothing matched". Results in the next section.
3. **13 October 2026 (UTC), keyword, scripted, for review round 2**: the GitHub Advisory Database's keyword search for uSHET's `cpp_magic.h` and fiat-crypto. Superseded by the fourth search, which repeats it.
4. **14 October 2026 (UTC), scripted, for review round 3**, which found that the searches above had left three vendored components unsearched or dismissed with wrong reasons (llhttp 9.3.0, BoringSSL by revision, BigInt). Two parts:
   - Every package, two more sources ([`advisories-search.log`](advisories-search.log), `commands/advisories-search.py`): the security advisories each package's repository publishes (GitHub's API; the forks' upstreams too), and NVD's keyword search by package name. Every advisory either lists needs a recorded verdict, or the search fails. This found three advisories Apple published in July 2026 in its own repositories that are in neither database the version-exact search reads (the Advisory Database lists a repository advisory only after GitHub reviews it), and an NVD record for SwiftNIO 1.x. None affects a pinned version.
   - The vendored code ([`vendored-advisories.log`](vendored-advisories.log), `commands/vendored-advisories.py`, replacing `vendored-advisories.sh`): llhttp 9.3.0 in OSV and the GitHub Advisory Database (npm); both BoringSSL revisions in OSV's commit index (OSV indexes BoringSSL from OSS-Fuzz as commit ranges); CryptoSwift's BigInt at every attaswift/BigInt 5.x and 6.x release (after finding the closest release by comparing the files); and every vendored component by keyword in the GitHub Advisory Database (every page) and NVD, and in its repository's published advisories. Each source carries a positive control. Results in the "Vendored components" table and the section "Review round 3 additions".

## Version-exact search (13 October 2026)

**Sources.** OSV (`POST https://api.osv.dev/v1/querybatch`): one query per package at its exact version (does any advisory affect this version?), and one per package with no version (which advisories exist for any version), then each advisory's record. OSV merges the GitHub Advisory Database, the OpenSSF malicious-packages feed and other ecosystem databases. GitHub (`GET https://api.github.com/advisories?ecosystem=…&affects=name@version,…`), unauthenticated, for reviewed advisories and for malware. `affects` returns an advisory when the version is inside its vulnerable range.

**Controls, and two limits they found.** Each ecosystem's queries include one package version with a known advisory, which each database must return:

| Ecosystem | Control | OSV | GitHub |
| --- | --- | --- | --- |
| npm | lodash 4.17.15, GHSA-p6mc-m468-83gw | returned | returned |
| Swift | marmelroy/Zip 2.1.2, GHSA-g454-wj9r-jpg4 (a pinned package; recorded under `github.com/marmelroy/Zip`) | returned | returned |
| Swift | apple/swift-crypto 4.3.0, GHSA-9m44-rr2w-ppp7 (recorded under the bare name `swift-crypto`) | returned | returned, asked on its own |
| PyPI | pyyaml 5.3, GHSA-8q59-q68h-6hv4 | returned | returned, asked as `PyYAML` on its own |
| GitHub Actions | actions/download-artifact 4.1.2, GHSA-cxww-7g56-2vh6 | **not returned** | returned |

- Package names are not spelled consistently, and GitHub matches `affects` names case-sensitively. GitHub records some PyPI names as published (`PyYAML`) and others normalized (`pyyaml`); a first run missed the PyPI control for that reason. Both databases record most Swift advisories under the repository URL's form (`github.com/apple/swift-nio`), but swift-crypto's GHSA-9m44-rr2w-ppp7 under the bare name `swift-crypto`, which a second run's any-version query missed for that reason. Every package is therefore sent in every spelling: each Python package as `requirements.txt` writes it, normalized and with underscores; each Swift package as its URL writes it, in lower case, and by its bare repository name in both cases. The second Swift control proves that a bare-named record is found. A control that shares a name with a pinned package is asked in a request of its own, because GitHub does not say which `name@version` matched.
- OSV evaluates no versions in the GitHub Actions ecosystem: it returns the download-artifact advisory for the package name, but not for 4.1.2, which is inside its range. For the actions, OSV's version result is not used. Its any-version query must list no advisory at all for each action, and it lists none.

## Method of the search by hand (12 October 2026)

1. **GitHub Advisory Database, Swift ecosystem, read in full.** `https://github.com/advisories?query=ecosystem%3Aswift`, pages 1 to 3: 64 advisories, which GitHub reviewed and mapped to Swift packages by repository URL. Each that names a pinned package was then opened for its affected and patched ranges.
2. **GitHub Advisory Database keyword search per package**, `https://github.com/advisories?query=<name>`. This also returns *unreviewed* advisories, which GitHub imports from the NVD without a package mapping, so a CVE that names a library only in its text still appears.
3. **OSV.dev, SwiftURL ecosystem** (`https://osv.dev/list?q=<name>&ecosystem=SwiftURL`), as a second source for the packages linked into the iOS app. OSV's SwiftURL entries are GitHub's advisories, and its text search is not exhaustive: it returned nothing for `swift-asn1` although GitHub lists GHSA-w8xv-rwgf-4fwh for it. GitHub was therefore the primary source. (The version-exact API search on 13 October found GHSA-w8xv-rwgf-4fwh in OSV as well.)
4. **Source at the pinned revision, for each advisory that names a pinned package or a vendored component**: whether the fix commit is an ancestor of the pinned revision (`git merge-base --is-ancestor` in the checkout that `commands/resolve-locks.sh` left), and whether the affected code is linked (`linkage.log`) and called.

## Review round 3 additions: repository advisories and NVD for every package (14 October 2026, UTC)

`advisories-search.log`, from `commands/advisories-search.py`, which now also reads two sources for every package in the inventory. Every advisory they list must have a verdict recorded in the script (`JUDGED`), or the search fails.

- **Repository security advisories** (`GET https://api.github.com/repos/<owner>/<repo>/security-advisories`), for each package's repository and the upstreams of the three forks (weichsel/ZIPFoundation, cezheng/Fuzi, swisspol/GCDWebServer). Positive control: apple/swift-nio must list GHSA-r3rc-9hpw-54v9. A project publishes these itself; the GitHub Advisory Database, which the version-exact search reads, lists one only after GitHub reviews it, and OSV takes them from there. Each advisory's range is checked against the pinned version by the script and compared with the recorded verdict. Result: 11 advisories, all from Apple's repositories (swift-nio 6, swift-nio-ssl 2, swift-crypto 2, swift-asn1 1), none affecting a pinned version; three were in neither database the version-exact search reads: GHSA-qcc5-f287-vgmq (swift-nio), GHSA-xfxg-9975-pc2j (swift-nio-ssl) and GHSA-8q93-f6xh-4f6f (swift-crypto), all published in July 2026 (rows in the next table). Every other repository publishes none.
- **NVD keyword search** (`https://services.nvd.nist.gov/rest/json/cves/2.0?keywordSearch=<keyword>`), by each package's name (26 keywords; positive control: "Zip Swift" must list CVE-2023-39135), at most 5 requests in 30 seconds. Result: CVE-2023-39135 applies (as recorded); the CVEs of the advisories above; CVE-2018-4281 (SwiftNIO before 1.8.0), new to this record and not affecting 2.103.0; and records for packages Sylvia does not pin (swift-nio-http2, swift-nio-ssh, SwiftNIO Extras), for readium-js, for the SwiftKey keyboard and for an unrelated product the keyword GRDB matched.

The fixes the round 3 verdicts rely on were checked in the package checkouts at the pinned revisions with `git merge-base --is-ancestor` (`round3-reproductions.log`): swift-crypto's `47d3869a` (the CVE-2026-43823 fix) is an ancestor of 5.0.0; the 2.37.2 release of swift-nio-ssl is an ancestor of 2.37.5; the 2.101.0 and 2.100.0 releases of swift-nio are ancestors of 2.103.0.
