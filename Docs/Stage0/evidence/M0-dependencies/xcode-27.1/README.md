# resolve-locks.sh and linkage.sh under Xcode 27.1, offline

ADR-0014's open item (review of the re-pin round, TC-05; the follow-up's finding OWN4-07) asked for `linkage.sh` to run under Xcode 27.1 (27A9275), the pin since 20 October 2026, after `resolve-locks.sh`, with its logs in a folder of their own, never over the Xcode 27.0 `linkage.log` and `resolve-locks.log` in the folder above, and for ADR-0014's section 4 to be brought up to date from it. Both scripts resolve packages, which can fetch from git remotes, and the agent that made these runs (at the M0 exit preparation, branch `m0-exit-zipguard`) may not fetch from a remote. So they ran **offline**: unchanged, with no git remote reachable, every pinned package taken from the local SwiftPM repository cache (`~/Library/Caches/org.swift.swiftpm/repositories`, which holds all 23 packages).

- **When and where:** 23 October 2026 UTC (24 October on the build Mac's clock), on the build Mac (macOS 26.6.2 (25G83), Apple M5 Max), Xcode 27.1 (27A9275), Swift 6.4, XcodeGen 2.46.0, on `5aec2518` (`main` after pull request #6, with `CLAUDE.md`'s correction), with no change under `Apps/`, `Packages/`, `Spikes/`, `Scripts/lib/` or the scripts' folder before or after (each `run-offline.log`). Other agents shared the Mac: the load is in each log, and the timings are indicative only. No simulator was booted: the iOS builds target a generic iOS Simulator destination.
- **How no remote was reached** (`commands/run-offline.sh`): `GIT_ALLOW_PROTOCOL=file`, so git refuses every transport but the local one and a clone, fetch or update from GitHub fails instead of reaching the network; `xcodebuild` reached through a shim on `PATH` that adds `-scmProvider system -skipPackageUpdates` to its package resolutions and builds, so Xcode uses that git and never updates a package from its remote; and `GIT_TRACE`, so every git command the run started is recorded. Each run's `git-network-check.log` counts those commands and lists every one that named a remote URL: each was refused (`transport 'https' not allowed`). Every build product under `Apps/`, `Packages/` and `Spikes/` was deleted before each run.

`resolve-locks.sh` lists 15 of the 16 committed locks: not the lock harness's (`Spikes/G05-Recovery/LockHarness`, added with PO-23 (b) on 22 October 2026, after the script was written), and `linkage.sh` does not build the harness either (its linkage was read separately: `Docs/Stage0/evidence/M0-Decisions/harness/checks/harness-linkage.log`, as `Docs/Licenses/inventory.json` records for GRDB).

- **GRDB's submodule.** GRDB.swift 7.11.1's `Package.swift` builds nothing from `SQLiteCustom/src`: its targets are `GRDBSQLite` (`Sources/GRDBSQLite`, a system library: SQLite is the system's) and `GRDB` (path `GRDB`); the submodule serves GRDB's own custom-SQLite Xcode project (`GRDBCustom.xcodeproj`) only. So leaving it empty changes nothing SwiftPM or Xcode compiles or links, and the GRDB counts in `run-2/linkage.log` are those of the code an online build compiles. An online run, which clones the submodule, would show it.
- **The IdentityProbe** (`Spikes/G03-Intake/ZipEval/IdentityProbe`, which has no lock by design, ADR-0010) is resolved without a lock, so SwiftPM updates the cached repositories first, and that update was refused: its expected refusal over the shared `zipfoundation` identity could not be shown offline. Its Xcode 27.0 result in `../resolve-locks.log` stands; nothing in `linkage.sh` depends on it.
- **What changed in what ships:** nothing third-party. `linkage-compare.log` (`commands/compare-linkage.py`) compares `run-2/linkage.log` with `../linkage.log` (Xcode 27.0, at `cfc5dea`) section by section: every third-party module and vendored library present or absent as before (0 changes of presence), each with the same symbol count except GRDB's in the host recovery tool (20,313 then, 20,318 now), and the same resource files. The other differences are Sylvia's own code, changed between the two commits: its modules' symbol counts, and five Apple system libraries the Mac source service now loads (CoreGraphics, CoreImage and three Swift overlays), which its QR-code pairing code brought (`Spikes/G02-Transfer/SourceService/Sources/SylviaSourceService/PairingQRCode.swift` imports CoreGraphics and CoreImage; merged at M0 assembly, after the Xcode 27.0 run). ADR-0014's section 4 records it.
